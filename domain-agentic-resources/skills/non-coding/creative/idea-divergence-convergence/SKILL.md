# Idea Divergence-Convergence

Run structured ideation cycles that alternate between divergent thinking (generating many ideas) and convergent thinking (selecting the best ones) to move from broad exploration to focused, testable concepts.

## When to Use This Skill

- Kicking off a new product, feature, or initiative and need many options
- Breaking out of a rut where the team keeps circling the same solution
- Running a structured brainstorm that avoids groupthink
- Evaluating a large set of ideas down to a few actionable concepts
- Facilitating innovation workshops or design sprints

## Core Concepts

### The Double Diamond Model

The Double Diamond (Design Council, 2005) frames creative work in four phases:

1. **Discover (Diverge)** — Explore the problem space broadly
2. **Define (Converge)** — Frame the specific problem to solve
3. **Develop (Diverge)** — Generate many possible solutions
4. **Deliver (Converge)** — Select and refine the best solution

**Diamond 1** explores the problem. **Diamond 2** explores the solution. Each has a divergent (opening) and convergent (closing) phase.

### Rules of Divergent Thinking

1. **Defer judgment** — No critiquing during generation
2. **Go for quantity** — More ideas = more raw material
3. **Build on others' ideas** — "Yes, and..." not "Yes, but..."
4. **Encourage wild ideas** — Extreme ideas often seed practical ones
5. **Stay visual** — Sketch, diagram, prototype over verbal-only

### Rules of Convergent Thinking

1. **Be deliberate** — Apply explicit criteria, not gut feeling
2. **Check for novelty** — Familiar ≠ best; actively protect novel ideas
3. **Cluster before killing** — Group related ideas; some weak ideas strengthen in combination
4. **Stay affirmative** — Look for what's strong in each idea before dismissing

## Workflow

### Phase 1: Frame the Challenge

1. Write a "How Might We" (HMW) statement:
   - Too narrow: "How might we add a chatbot to the homepage?"
   - Too broad: "How might we improve the user experience?"
   - Right: "How might we help new users discover value within their first session?"
2. Set constraints: timeline, budget, technical limits, must-haves
3. Identify who should participate (diverse perspectives improve output)

### Phase 2: Diverge — Generate Ideas

Choose 2-3 techniques:

**SCAMPER** — Apply transformations to existing solutions:
- **S**ubstitute, **C**ombine, **A**dapt, **M**odify, **P**ut to another use, **E**liminate, **R**everse

**Brainwriting (6-3-5)** — 6 people, 3 ideas each, 5 minutes per round. Silent generation avoids groupthink.

**Random Stimulus** — Pick a random word, image, or object. Force connections to the challenge.

**Worst Possible Idea** — Generate the worst solutions, then invert them into viable ideas.

**Assumption Reversal** — List assumptions about the problem, reverse each one, and ideate from the reversal.

**Target:** Generate 30-100+ raw ideas. Quantity is the goal.

### Phase 3: Converge — Cluster and Filter

1. **Affinity mapping**: Group similar ideas into 5-10 themed clusters
2. **Name each cluster** with a descriptive theme label
3. **Dot voting**: Each participant gets 3-5 votes on clusters
4. **Top clusters advance**: Take the top 3-5 clusters forward

### Phase 4: Diverge Again — Develop Top Concepts

For each surviving cluster:
1. Combine strongest ideas within the cluster into a concept sketch
2. Explore variations: "What if we did this but also...?"
3. Identify the riskiest assumption in each concept
4. Sketch a simple user journey or scenario

### Phase 5: Converge — Select and Prioritize

**Impact/Effort Matrix:**
- High Impact + Low Effort = Quick Wins
- High Impact + High Effort = Strategic Bets
- Low Impact + Low Effort = Fill-in Work
- Low Impact + High Effort = Avoid

**NUF Test** (score 1-10 each):
- **N**ew — Is this genuinely novel?
- **U**seful — Does this solve the real problem?
- **F**easible — Can we actually build this?

**Output:** 1-3 concepts to prototype or test.

### Phase 6: Define Next Steps

For each selected concept:
1. Write a one-paragraph concept statement
2. Identify the riskiest assumption to test first
3. Define a lightweight experiment or prototype
4. Assign an owner and timeline

## Templates

### HMW Statement Template

```
How might we [action verb] [user/stakeholder] to [desired outcome]
given [key constraint]?
```

### Concept Card Template

```markdown
## Concept: [Name]

**One-liner:** [What it is in one sentence]
**How it works:** [3 steps]
**Key benefit:** [Primary value proposition]
**Riskiest assumption:** [What must be true]
**First test:** [Cheapest validation method]
**NUF Score:** New: _/10  Useful: _/10  Feasible: _/10  Total: _/30
```

## Best Practices

- **Timebox every phase**: Use 10-15 minute sprints. Divergence without deadlines becomes aimless.
- **Separate divergence from convergence**: Don't evaluate in the same session you generate.
- **Diverse participants beat expert panels**: Mix roles, seniority, and disciplines.
- **Write before you talk**: Silent generation before group discussion prevents anchoring.
- **Protect novelty during convergence**: Ask "are we killing this because it's unfamiliar or because it's bad?"
- **Document everything**: Rejected ideas may become relevant later.
- **Iterate the cycle**: Run 2-3 diverge-converge cycles with increasing fidelity.

## Common Pitfalls

| Pitfall | Why It Happens | How to Avoid |
|---------|----------------|--------------|
| HiPPO effect | Highest-paid person dominates | Use silent brainwriting; anonymous voting |
| Premature convergence | Team jumps to solutions too fast | Enforce "no critique" rule during divergence |
| Anchoring on first idea | First idea shared sets the frame | Require individual ideation before sharing |
| Killing novelty | Unfamiliar = risky in convergence | Add a "novelty bonus" in scoring criteria |
| Idea hoarding | Participants save their best | Warm up with bad/silly ideas first |
| Convergence fatigue | Too many ideas to evaluate | Cluster before evaluating; vote on themes |

## Quality Checklist

- [ ] HMW statement is neither too broad nor too narrow
- [ ] Divergent phase generated 30+ raw ideas
- [ ] Multiple ideation techniques used (not just verbal brainstorm)
- [ ] Ideas generated silently before group discussion
- [ ] Convergence used explicit criteria (not just gut voting)
- [ ] Novel ideas explicitly protected during filtering
- [ ] Top concepts have a clear riskiest assumption identified
- [ ] Each selected concept has a defined next step and owner
- [ ] Rejected ideas documented (not discarded)

## Examples

### Example: Feature Ideation Sprint (90 minutes)

**Challenge:** "How might we help remote teams build trust without increasing meeting load?"

| Phase | Time | Activity | Output |
|-------|------|----------|--------|
| Frame | 10 min | Write HMW, set constraints | HMW statement + 3 constraints |
| Diverge 1 | 20 min | Brainwriting (6-3-5) + SCAMPER | 54 raw ideas on cards |
| Converge 1 | 15 min | Affinity map + dot vote | 6 clusters, top 3 selected |
| Diverge 2 | 20 min | Concept sketches for top 3 | 3 concept cards with journeys |
| Converge 2 | 15 min | NUF scoring + discussion | 1 concept selected |
| Next steps | 10 min | Define experiment + owner | Experiment brief assigned |
