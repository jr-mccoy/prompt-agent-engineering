# Curriculum Design

Design coherent, outcomes-aligned learning programs that connect what learners should know, how they'll practice, and how mastery is assessed.

## When to Use This Skill

- Building a new course, workshop series, or training pathway
- Redesigning an existing curriculum that isn't achieving outcomes
- Aligning a program to new standards, competencies, or credentialing requirements
- Creating corporate training or onboarding curricula
- Mapping prerequisites and scaffolding across a multi-course program

## Core Concepts

### Backward Design (Understanding by Design)

Wiggins & McTighe's framework starts from the end:

1. **Stage 1: Identify Desired Results** — What should learners know and be able to do?
2. **Stage 2: Determine Acceptable Evidence** — How will you know they've learned it?
3. **Stage 3: Plan Learning Experiences** — What activities will get them there?

This reverses the common mistake of starting with activities ("let's do a group project") without first defining what success looks like.

### Constructive Alignment (Biggs)

Every component of the curriculum must align:

```
Learning Outcomes ←→ Teaching Activities ←→ Assessment Tasks
```

If the outcome is "analyze," but the activity is "listen to lecture" and the assessment is "recall facts," the system is misaligned.

### Learning Outcomes Taxonomy

Use Bloom's Taxonomy (revised) to write measurable outcomes:

| Level | Verbs | Example |
|-------|-------|---------|
| Remember | List, define, recall | List the 5 principles of... |
| Understand | Explain, summarize, classify | Explain why X causes Y |
| Apply | Use, implement, solve | Solve a problem using framework X |
| Analyze | Compare, differentiate, examine | Compare approaches A and B |
| Evaluate | Justify, critique, recommend | Recommend the best approach for... |
| Create | Design, construct, produce | Design a system that... |

### Scaffolding Principle

Complex skills are built from simpler prerequisite skills. Map dependencies explicitly:

```
Design a full system (Create)
  ├── Evaluate component trade-offs (Evaluate)
  │     ├── Analyze component interactions (Analyze)
  │     │     ├── Apply individual components (Apply)
  │     │     │     └── Understand component purpose (Understand)
  │     │     └── Understand system constraints (Understand)
  │     └── Apply evaluation criteria (Apply)
  └── Construct integration plan (Create)
```

## Workflow

### Phase 1: Needs Analysis

1. Identify the target learner profile (prior knowledge, motivation, constraints)
2. Define the program scope and context (academic, corporate, self-paced)
3. Gather stakeholder requirements (employers, accreditors, learners)
4. Identify existing resources and constraints (time, tools, instructors)
5. Benchmark against comparable programs

### Phase 2: Define Learning Outcomes

1. Write 3-7 program-level outcomes using Bloom's verbs
2. Decompose each into module-level outcomes
3. Ensure outcomes span multiple Bloom's levels (not all "remember")
4. Verify outcomes are measurable (avoid "understand" without an observable indicator)
5. Validate with stakeholders: "If learners can do these things, is that success?"

### Phase 3: Design Assessment Strategy

For each outcome, define how you'll measure it:

| Assessment Type | Best For | Examples |
|----------------|----------|---------|
| Formative | Ongoing feedback, self-check | Quizzes, peer review, reflections |
| Summative | Final demonstration of mastery | Projects, exams, portfolios |
| Authentic | Real-world transfer | Case studies, simulations, client work |

Apply the **alignment test**: Does this assessment actually measure the stated outcome?

### Phase 4: Scope and Sequence

1. Group outcomes into logical modules/units (4-8 per course)
2. Order modules based on prerequisite dependencies
3. Allocate time per module based on complexity and Bloom's level
4. Build in review, practice, and assessment checkpoints
5. Plan the "spiral" — key concepts revisited at increasing depth

### Phase 5: Design Learning Activities

For each module, select activities aligned to the outcome's Bloom's level:

| Bloom's Level | Effective Activities |
|---------------|---------------------|
| Remember/Understand | Readings, videos, concept maps, guided notes |
| Apply | Practice problems, simulations, labs, case studies |
| Analyze/Evaluate | Debates, comparative analysis, peer review, critiques |
| Create | Projects, design challenges, portfolios, prototypes |

### Phase 6: Differentiation and Accessibility

1. Provide multiple means of engagement (choice, relevance, self-regulation)
2. Provide multiple means of representation (text, visual, audio, interactive)
3. Provide multiple means of action and expression (varied assessment options)
4. Plan for prerequisite gaps (remedial pathways, office hours, tutoring)

## Templates

### Module Design Template

```markdown
## Module [N]: [Title]

**Duration:** [X hours/weeks]
**Prerequisites:** [Module N-1, specific prior knowledge]

### Learning Outcomes
By the end of this module, learners will be able to:
1. [Bloom's verb] + [specific, measurable outcome]
2. [Bloom's verb] + [specific, measurable outcome]

### Key Topics
- [Topic 1]
- [Topic 2]

### Activities
| Activity | Type | Duration | Outcome Addressed |
|----------|------|----------|-------------------|
| [Name] | Lecture/Lab/Discussion | [Time] | Outcome 1 |

### Assessment
- **Formative:** [Quiz, reflection, peer review]
- **Summative:** [Project, exam, portfolio piece]

### Resources
- [Required readings/tools]
```

## Best Practices

- **Start from outcomes, not content**: The question is "what should they be able to DO?" not "what topics should we cover?"
- **Align everything**: Every activity should serve an outcome; every assessment should measure one.
- **Vary Bloom's levels**: A curriculum stuck at "remember" produces test-passers, not practitioners.
- **Build in retrieval practice**: Spaced repetition and low-stakes quizzes improve long-term retention.
- **Pilot before scaling**: Test the curriculum with a small cohort and iterate.
- **Include metacognitive activities**: Reflections and self-assessments build learner autonomy.
- **Plan for the whole learner**: Time, energy, and motivation are finite resources to manage.

## Common Pitfalls

| Pitfall | Why It Happens | How to Avoid |
|---------|----------------|--------------|
| Content-first design | Easier to list topics than define outcomes | Use backward design (outcomes first) |
| Assessment-outcome misalignment | Assessment tests different skills than outcomes state | Apply alignment test to every assessment |
| Bloom's floor | All outcomes at remember/understand level | Ensure at least 40% of outcomes at apply+ |
| Missing prerequisites | Assumed knowledge not verified | Map prerequisite dependencies explicitly |
| Overloaded modules | Too many outcomes per module | Limit to 2-4 outcomes per module |
| No formative feedback | Only summative assessment at the end | Add low-stakes checkpoints throughout |

## Quality Checklist

- [ ] Program-level outcomes are measurable with Bloom's verbs
- [ ] Each module outcome maps to a program outcome
- [ ] Every assessment measures at least one stated outcome
- [ ] Activities are aligned to the Bloom's level of the outcome
- [ ] Modules are ordered by prerequisite dependency
- [ ] At least 40% of outcomes are at Apply level or above
- [ ] Both formative and summative assessments are included
- [ ] Differentiation strategies address diverse learner needs
- [ ] Total learner time is realistic and budgeted
- [ ] Curriculum reviewed by subject-matter expert and instructional designer

## Examples

### Example: 12-Week Data Analytics Bootcamp

| Week | Module | Bloom's Focus | Assessment |
|------|--------|---------------|------------|
| 1-2 | Data Fundamentals | Remember, Understand | Quiz + reflection |
| 3-4 | SQL & Data Wrangling | Apply | Lab exercises |
| 5-6 | Statistical Analysis | Apply, Analyze | Case study analysis |
| 7-8 | Visualization & Storytelling | Apply, Create | Dashboard project |
| 9-10 | Machine Learning Basics | Understand, Apply | Model building lab |
| 11-12 | Capstone Project | Analyze, Evaluate, Create | End-to-end project |
