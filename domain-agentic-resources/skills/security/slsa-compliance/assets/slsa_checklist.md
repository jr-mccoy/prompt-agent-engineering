# SLSA Compliance Checklist

> Complete level-by-level checklist for achieving SLSA compliance.

---

## How to Use This Checklist

1. **Start at Level 1** - Complete all Level 1 requirements before moving to Level 2
2. **Check each item** - Mark items as you complete them
3. **Document evidence** - Keep records of how each requirement is met
4. **Review regularly** - Re-validate compliance after changes to build process

---

## Level 0 → Level 1: Foundation

> **Goal:** Establish basic provenance generation

### Build Documentation

- [ ] **L1-DOC-01:** Build process is documented
  - Location: README.md, BUILDING.md, or docs/
  - Content: Dependencies, build commands, output artifacts

- [ ] **L1-DOC-02:** Build is scripted (not manual)
  - Evidence: Makefile, build script, or CI config

- [ ] **L1-DOC-03:** Build dependencies are listed
  - Format: requirements.txt, package.json, go.mod, etc.

### Provenance Generation

- [ ] **L1-PROV-01:** Provenance is generated for releases
  - Tool: GitHub Actions, custom script, etc.
  - Format: in-toto attestation, SLSA provenance

- [ ] **L1-PROV-02:** Provenance contains builder identity
  ```json
  "builder": {
    "id": "https://github.com/actions/runner"
  }
  ```

- [ ] **L1-PROV-03:** Provenance contains source reference
  ```json
  "materials": [{
    "uri": "git+https://github.com/org/repo",
    "digest": {"sha1": "abc123..."}
  }]
  ```

- [ ] **L1-PROV-04:** Provenance contains build configuration
  ```json
  "invocation": {
    "configSource": {
      "uri": "git+https://github.com/org/repo",
      "entryPoint": ".github/workflows/release.yml"
    }
  }
  ```

### SBOM (Recommended)

- [ ] **L1-SBOM-01:** SBOM generated for releases
  - Format: SPDX or CycloneDX
  - Tool: Syft, cdxgen, Trivy

- [ ] **L1-SBOM-02:** SBOM includes all dependencies
  - Direct and transitive dependencies
  - Verified: Component count is reasonable

## Level 1 → Level 2: Tamper Resistance

> **Goal:** Prevent tampering by using hosted builds and signed provenance

### Version Control

- [ ] **L2-VCS-01:** Source code in version control
  - System: Git (GitHub, GitLab, Bitbucket)
  - Evidence: .git directory exists

- [ ] **L2-VCS-02:** Releases created from tags
  - Evidence: Releases reference git tags (v1.0.0, etc.)

- [ ] **L2-VCS-03:** Main branch protection enabled
  - GitHub: Branch protection rules
  - GitLab: Protected branches

### Hosted Build Service

- [ ] **L2-BUILD-01:** Builds run on hosted CI/CD
  - Platform: GitHub Actions, GitLab CI, etc.
  - Evidence: CI configuration file exists

- [ ] **L2-BUILD-02:** No local machine builds for releases
  - Process: All releases through CI pipeline
  - Evidence: Release artifacts from CI only

- [ ] **L2-BUILD-03:** Build logs are retained
  - Duration: Minimum 30 days
  - Access: Team members can review

### Authenticated Provenance

- [ ] **L2-SIGN-01:** Provenance is signed
  - Method: Sigstore keyless, GPG, cosign with key
  - Evidence: Signature file exists

- [ ] **L2-SIGN-02:** Signature can be verified
  ```bash
  # Keyless (Sigstore)
  cosign verify-blob --certificate cert.pem --signature sig provenance.json

  # Key-based
  cosign verify-blob --key cosign.pub --signature sig provenance.json
  ```

- [ ] **L2-SIGN-03:** Signing identity is documented
  - For keyless: OIDC issuer and subject pattern
  - For key-based: Public key location

### Dependency Management

- [ ] **L2-DEP-01:** Dependencies use lockfiles
  - Files: package-lock.json, go.sum, Cargo.lock, etc.

- [ ] **L2-DEP-02:** Lockfiles committed to repository
  - Evidence: Lockfiles in version control

- [ ] **L2-DEP-03:** Dependency updates reviewed
  - Process: Dependabot, Renovate, or manual review

## Level 2 → Level 3: Hardened Builds

> **Goal:** Ensure provenance cannot be falsified by the build job itself

### Non-Falsifiable Provenance

- [ ] **L3-NFPROV-01:** Provenance generated by isolated service
  - GitHub: SLSA GitHub Generator reusable workflow
  - Other: Separate, protected workflow/job

- [ ] **L3-NFPROV-02:** Build job cannot modify provenance
  ```yaml
  # Build and provenance in separate jobs
  jobs:
    build:
      # ... outputs hash only
    provenance:
      # ... generates provenance from hash
      uses: slsa-framework/slsa-github-generator/...
  ```

- [ ] **L3-NFPROV-03:** Provenance workflow version pinned
  ```yaml
  # Use full SHA or version tag
  uses: slsa-framework/slsa-github-generator/.github/workflows/generator_generic_slsa3.yml@v2.0.0
  ```

### Build Isolation

- [ ] **L3-ISO-01:** Builds run in ephemeral environment
  - GitHub: GitHub-hosted runners (default)
  - Self-hosted: Ephemeral VMs/containers

- [ ] **L3-ISO-02:** Build environment is minimal
  - Only necessary tools installed
  - No shared state between builds

- [ ] **L3-ISO-03:** Secrets are scoped appropriately
  - Principle of least privilege
  - No unnecessary secret access

### Hermetic Builds (Recommended)

- [ ] **L3-HERM-01:** Dependencies pre-fetched
  - Method: Vendor, cache, or mirror
  - Evidence: Build works without network

- [ ] **L3-HERM-02:** Network access disabled during build
  - Method: Network policy, sandbox
  - Evidence: Build succeeds with network blocked

- [ ] **L3-HERM-03:** Build inputs fully declared
  - All dependencies in lockfiles
  - No implicit downloads during build

### Entry Point Control

- [ ] **L3-ENTRY-01:** Build triggered by fixed configuration
  - Config file in repository (not parameters)
  - Evidence: Workflow/Makefile defines build

- [ ] **L3-ENTRY-02:** Build parameters are logged
  - Environment variables captured in provenance
  - Evidence: Parameters visible in provenance

- [ ] **L3-ENTRY-03:** Manual overrides are prevented or logged
  - No way to skip steps or modify build
  - Evidence: Workflow doesn't use inputs for build commands

## Level 3 → Level 4: Maximum Assurance (Future)

> **Goal:** Multi-party verification and reproducibility

### Two-Party Review

- [ ] **L4-2PR-01:** All code changes require 2+ reviewers
  - GitHub: CODEOWNERS + required reviews
  - Evidence: PR history shows multiple approvers

- [ ] **L4-2PR-02:** Automated checks must pass
  - Tests, linting, security scans
  - Evidence: Required status checks configured

- [ ] **L4-2PR-03:** Force push disabled on protected branches
  - Evidence: Branch protection settings

### Reproducible Builds

- [ ] **L4-REPRO-01:** Build is deterministic
  - Same inputs → same outputs
  - Evidence: Hash matches across builds

- [ ] **L4-REPRO-02:** Timestamps eliminated or controlled
  - Embedded timestamps made reproducible
  - Evidence: SOURCE_DATE_EPOCH set

- [ ] **L4-REPRO-03:** Build environment fully specified
  - Dockerfile or Nix expression
  - Evidence: Environment recreatable

### Multi-Platform Attestation

- [ ] **L4-MULTI-01:** Multiple independent builders attest
  - Different CI platforms
  - Evidence: Multiple provenance files

- [ ] **L4-MULTI-02:** Attestations are compared
  - Hash matching verified
  - Evidence: Verification script

## Additional Best Practices

### Security Controls

- [ ] **BP-SEC-01:** Secrets not exposed in logs
  - Masked in CI output
  - Evidence: Log review

- [ ] **BP-SEC-02:** Credentials rotated regularly
  - Schedule: Minimum quarterly
  - Evidence: Rotation records

- [ ] **BP-SEC-03:** Vulnerability scanning enabled
  - Dependencies: Dependabot, Snyk, etc.
  - Container images: Trivy, Grype

### Verification

- [ ] **BP-VER-01:** Provenance verified before deployment
  - Tool: slsa-verifier, cosign verify
  - Evidence: Verification in deployment pipeline

- [ ] **BP-VER-02:** SBOM used for vulnerability tracking
  - Integration: Dependency-Track, Grype
  - Evidence: SBOM ingested

- [ ] **BP-VER-03:** Admission control enforces signatures
  - Kubernetes: Sigstore Policy Controller, Kyverno
  - Evidence: Policy configured

### Documentation

- [ ] **BP-DOC-01:** SLSA level documented
  - Location: README, security policy
  - Content: Current level and evidence

- [ ] **BP-DOC-02:** Verification instructions provided
  ```bash
  # Document how to verify releases
  slsa-verifier verify-artifact artifact \
    --provenance-path provenance.intoto.jsonl \
    --source-uri github.com/org/repo
  ```

- [ ] **BP-DOC-03:** Incident response plan includes supply chain
  - Plan: How to respond to compromised dependency
  - Evidence: Documented procedure

## Quick Assessment Commands

```bash
# Check for CI configuration
ls -la .github/workflows/ .gitlab-ci.yml Jenkinsfile 2>/dev/null

# Check for lockfiles
ls -la package-lock.json yarn.lock go.sum Cargo.lock 2>/dev/null

# Check for SBOM
ls -la sbom.* bom.* *.spdx.json *.cdx.json 2>/dev/null

# Check for provenance
ls -la *.intoto.jsonl provenance.json *.att 2>/dev/null

# Run SLSA level checker
python slsa_level_checker.py --path . --output text
```
