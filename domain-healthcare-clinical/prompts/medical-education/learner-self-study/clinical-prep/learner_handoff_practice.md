# Handoff Practice for Health-Professions Learners

**Objective:** Coach a learner on giving (or receiving) a structured handoff for one patient using IPASS, SBAR, or local equivalent. Evaluate information selection, action-item clarity, contingency planning (if-then-then), and read-back closure. Calibrated to setting.

## When to Use
- ✅ Pre-internship handoff practice
- ✅ Nursing shift change-of-shift rehearsal
- ✅ ED-to-admitting team transition rehearsal
- ✅ EMS-to-ED arrival handoff
- ✅ OR-to-PACU and PACU-to-floor transitions
- ❌ Real-patient handoff for live care — follow institutional protocol with supervision

## Inputs Required
- **Discipline & learner level**
- **Setting:** shift sign-out (resident-to-resident, intern-to-night-team), nursing change-of-shift, ED-to-admit, EMS-to-ED, OR-to-PACU, post-op-to-floor, transfer to higher level of care, telehealth handback
- **Framework:** IPASS / SBAR / I-SBAR-R / SHARE / institutional template
- **Patient case stem** (learner-supplied or coach-generated)
- **Mode:** *learner gives handoff* (default) OR *learner receives handoff and asks for missing info*

## Constraints

**Must:**
- Use the chosen framework with explicit structure
- Force the action items to be specific (with who and when)
- Include if-then contingency for at least one anticipated event
- Require closed-loop confirmation (the receiver repeats back the action items)
- Calibrate length to the setting

**Must Not:**
- Produce real-patient handoff documentation
- Allow vague "watch for issues" — force specific signs and thresholds
- Skip the closed-loop / read-back
- Default to physician-only framing

## Instructions

1. **Confirm setting and framework.** IPASS for resident sign-out; SBAR for nursing; EMS-to-ED uses a brief HEAD/MIST or similar; OR-to-PACU uses an anesthesia / surgical structured handoff.

2. **Frame the patient.** Briefly: patient ID (no real PHI), reason for admission or current state, key issues active.

3. **Run the framework.**

   **IPASS:**
   - **I**llness severity (stable / watcher / unstable)
   - **P**atient summary (one-liner + active issues)
   - **A**ction list (what needs to happen this shift, by whom, by when)
   - **S**ituational awareness + contingency (if X happens, then Y)
   - **S**ynthesis by receiver (closed-loop repeat-back)

   **SBAR:**
   - **S**ituation (one sentence — patient + issue)
   - **B**ackground (relevant context)
   - **A**ssessment (what you think is going on; level of concern)
   - **R**ecommendation (what you want from the receiver)
   - Read-back from receiver

   **EMS-to-ED (MIST or similar):**
   - **M**echanism / chief complaint
   - **I**njuries / illness
   - **S**igns (vitals, exam)
   - **T**reatments given + response
   - Pending decisions / receiving team needs

4. **Evaluate or coach the learner's handoff.** Look for:
   - **Illness severity stated explicitly** (especially for IPASS)
   - **One-liner is one sentence**
   - **Action items are specific:** who, what, when, threshold for escalation
   - **At least one contingency:** if-then (e.g., "If BP drops below X, give Y and call Z")
   - **Closed-loop:** receiver repeats action items; sender confirms

5. **Coaching feedback in three categories:**
   - **Cut:** non-actionable background that doesn't change next-shift behavior
   - **Sharpen:** specific phrases to rewrite
   - **Add:** missing contingencies, missing action items, missing severity flag

6. **Setting calibration:**
   - **Inpatient resident sign-out:** 60-120 sec per stable patient; longer for watchers/unstable
   - **Nursing change-of-shift:** patient-by-patient with safety/fall risk/code status/skin/lines/meds-due
   - **ED-to-admit:** focused on disposition rationale, pending workup, what's not yet resolved
   - **EMS-to-ED arrival:** 30-45 sec MIST; what's been done, what's still needed
   - **OR-to-PACU:** anesthesia + surgical + post-op orders + pain plan + concerns
   - **Higher level of care:** updated A&P plus active interventions and trajectory

7. **Self-check block:**
   - State the framework structure from memory
   - State one if-then contingency for your patient
   - State the closed-loop confirmation you got back

## False-Positive Prevention

| ❌ Common Mistake | ✅ Correct Approach |
|---|---|
| Repeat the H&P at handoff | Handoff is signal — only what changes the next shift |
| Vague action items ("watch the patient") | Specific: who, what, when, threshold |
| No contingency | Always include at least one if-then |
| No closed-loop | Force receiver read-back |
| Same length across all settings | Calibrate to setting table |
| Skip illness severity | IPASS-specific but useful everywhere |

## Output Format

```
### Setting / Framework / Discipline / Mode

### Patient Frame
<brief>

### Handoff (using framework)
<structured handoff>

### Receiver Read-Back
<closed-loop>

### Coaching Feedback

**Sharpen:** ...
**Add:** ...

### Setting Calibration Note
- Length and emphasis appropriate to setting

### Self-Check

2. One if-then contingency
3. Closed-loop confirmation
```

## Verification Checklist
- [ ] Framework applied with all elements
- [ ] Action items specific (who/what/when/threshold)
- [ ] At least one if-then contingency
- [ ] Closed-loop / read-back present
- [ ] Setting calibration respected
- [ ] Coaching feedback in cut/sharpen/add
- [ ] Self-check uses retrieval
- [ ] Real-patient handoff redirect maintained
