# EPA Implementation Designer

**Objective:** Design complete implementation for a specific Entrustable Professional Activity (EPA): EPA title and description, knowledge-skills-attitudes required, entrustment-supervision scale, evidence requirements for each entrustment level, observation protocols, entrustment-decision logic, expected trajectory across training, and assessor training.

## When to Use
- ✅ Implementing a new EPA in a residency or fellowship program
- ✅ Implementing AAMC Core EPAs for medical school graduates
- ✅ Operationalizing a specialty board's EPA framework at program level
- ✅ Auditing an in-flight EPA implementation
- ❌ Building the full CBME roadmap (use `meded_cbme_implementation_program.md`)
- ❌ Mapping multiple EPAs to rotations (use `meded_residency_curriculum_mapper.md`)

## Inputs Required
- **EPA identity:** title, source (specialty board, AAMC, locally developed), version
- **Description and clinical context** in which the EPA is performed
- **Knowledge, skills, attitudes** required for entrustment
- **Entrustment scale** (typically 1-5: observation only → unsupervised → supervisor of others)
- **Expected trajectory:** when in training does the EPA progress through entrustment levels
- **Existing assessment tools** the program uses

## Constraints

**Must:**
- Define EPA in observable, integrative terms (combines multiple competencies)
- Specify the entrustment-supervision scale with each level's behavioral anchor
- Identify required evidence types for each entrustment level (more evidence at higher levels)
- Specify observation protocols (who, how often, in what contexts)
- Build entrustment-decision logic (who decides, how aggregated, what counts)
- Build the trajectory: what entrustment level is expected at each PGY year
- Address common pitfalls (entrustment inflation, halo effects, demographic bias)

**Must Not:**
- Define EPA as a single competency (EPAs are integrative)
- Use entrustment scale levels interchangeably (each level has specific behavioral meaning)
- Make entrustment decisions on single observations
- Skip assessor training (entrustment decisions are skill-dependent)
- Ignore bias monitoring

## Instructions

1. **Confirm EPA.** Echo title, source, version, description, clinical context.

2. **Define the EPA clearly.**
   - Title (action-oriented, observable)
   - Brief description (1-2 sentences)
   - Clinical context (where, when performed)
   - Specifications (what's included, what's not — useful when EPA could be interpreted broadly)

3. **Articulate KSA requirements.**
   - Knowledge required
   - Skills required (technical + cognitive)
   - Attitudes / professionalism elements
   - Linked Milestones / Competencies the EPA integrates

4. **Specify entrustment-supervision scale.**
   - Level 1: Permitted to observe only (no execution)
   - Level 2: Permitted to execute with direct supervision (supervisor in room)
   - Level 3: Permitted to execute with indirect supervision (supervisor available)
   - Level 4: Permitted to execute independently (no supervision)
   - Level 5: Permitted to supervise others performing the activity

   For each level, provide behavioral anchors (what behavior characterizes a learner at this level).

5. **Specify evidence requirements per level.**
   - Level 2: foundational evidence; supervisor confidence in fundamentals
   - Level 3: progressive evidence; multiple successful observations; absence of red flags
   - Level 4: substantial evidence; multiple sites, multiple supervisors, complex cases
   - Level 5: evidence of supervisory skill

6. **Specify observation protocols.**
   - Who observes (assessor type)
   - Frequency
   - Context variation (different patients, different conditions, different sites)
   - Documentation (specific WBA tool or narrative format)

7. **Build entrustment-decision logic.**
   - Who decides (single supervisor, group, CCC)
   - How aggregated (single observer recommendation, group consensus, weighted)
   - What evidence required
   - Time interval (no entrustment decision based on one rotation alone unless explicitly designed)

8. **Specify trajectory.**
   - By PGY year, expected entrustment level
   - Acceptable variation (some learners advance faster, some slower)
   - Triggers for individualized learning plan

9. **Build assessor training.**
   - EPA definition and scope
   - Entrustment scale behavioral anchors (calibration)
   - Frame-of-reference training
   - Bias awareness (gender, race, IMG status patterns in entrustment)

10. **Build implementation infrastructure.**
    - Documentation system
    - Learner dashboard
    - CCC review interface
    - Reporting

## False-Positive Prevention

| Common Mistake | Why It's Wrong | Correct Approach |
|---|---|---|
| EPA = single competency | Misses integrative purpose | EPA integrates multiple competencies |
| Entrustment scale levels interchangeable | Each level has specific behavioral meaning | Anchor every level with behaviors |
| Single observation = entrustment | Reliability suffers | Multiple observations, multiple sites, multiple supervisors |
| No assessor training | Inconsistent decisions; bias amplified | Build calibration into the system |
| Trajectory rigid | Variable learner pace expected | Acceptable range, not single target |
| No bias monitoring | Disparate entrustment hidden | Build monitoring; surface patterns |
| Evidence at low level = sufficient at high level | Higher entrustment needs more evidence | Specify evidence scaling |
| Locally defined without specialty alignment | Misses interoperability | Align to specialty body's EPAs when available |
