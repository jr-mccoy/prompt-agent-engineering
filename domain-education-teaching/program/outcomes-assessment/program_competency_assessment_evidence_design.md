# Competency Assessment Evidence Design

**Objective:** Design a multi-source, multi-occasion evidence plan for competency-based assessment — combining direct observation, work products, simulation performance, multi-source feedback (360°), learner-generated artifacts, and outcome data — with sampling frequency, scoring tools, and a decision framework that aggregates evidence into entrustment or progression decisions.

## When to Use
- ✅ Competency-based medical education (CBME) implementation: EPAs, milestones, entrustment decisions
- ✅ Workforce competency assessment: journey-level demonstration, supervisor sign-off
- ✅ HE competency-based programs (CBE): demonstration of mastery rather than seat time
- ✅ Apprenticeship competency demonstration
- ❌ Single-occasion test design (use the assessment blueprint builder)
- ❌ Defining competencies (use the competency framework designer)

## Inputs Required
- **Competency framework:** competencies/EPAs/milestones with IDs and descriptions
- **Learner population and time horizon**
- **Settings available for assessment:** workplace, simulation, classroom, portfolio
- **Available assessors:** supervisors, peers, patients/clients, self, expert raters
- **Existing assessment tools** (optional): mini-CEX, DOPS, CbD, OSCEs, in-training exams, work-product rubrics
- **Decision points and stakes:** formative feedback / progression / certification / entrustment
- **Regulatory / accreditor requirements**

## Constraints

**Must:**
- For every competency, ≥3 evidence sources from different modalities (triangulation)
- ≥1 evidence source must be direct observation in authentic context
- Specify sampling frequency adequate for reliability (typically multiple samples per competency)
- Tie every evidence source to a scoring tool (rubric, behavioral anchored scale, entrustment scale)
- Build the aggregation rule (how evidence rolls into a decision)
- Address bias and assessor calibration

**Must Not:**
- Rely on single-occasion or single-rater evidence for high-stakes decisions
- Use indirect proxies (knowledge tests alone) as evidence of integrative competency
- Treat learner self-report as primary evidence
- Skip authentic-context observation
- Generate an evidence plan that exceeds assessor capacity

## Instructions

1. **Confirm inputs.** Echo framework, competencies, settings, assessors, tools, stakes.

2. **For each competency, identify evidence sources from at least three modalities:**
   - **Direct observation:** workplace-based assessment (mini-CEX, DOPS, CbD, observed clinical/work performance, journey-test demonstration)
   - **Work product:** chart, code, report, artifact, project deliverable
   - **Simulation:** OSCE, simulated client, role play, scenario task
   - **Multi-source feedback:** peer, supervisor, patient/client, self
   - **Outcome data:** patient outcomes, code quality metrics, client satisfaction, production output
   - **Knowledge / cognitive:** in-training exam, certification practice test

3. **Specify sampling frequency.**
   - Initial competency: lower frequency, more direct supervision
   - Developing: increasing frequency, increasing independence
   - Master / entrustable: confirmation through multiple authentic-context observations

4. **Match scoring tools.**
   - Mini-CEX: 9-point scale anchored to descriptors
   - DOPS: structured behavioral checklist
   - Entrustment-supervision scale: 1 (observation only) → 5 (unsupervised, can teach others)
   - Milestone narratives: structured prose with anchors
   - Work-product rubrics: criterion × level matrices

5. **Build the aggregation rule.**
   - How does evidence roll up to a competency-level judgment?
   - Who decides? (committee, single supervisor, algorithm)
   - When? (semi-annual review, milestone meetings, end-of-rotation)
   - What threshold? (proportion of observations at target level, lack of red-flag observations)

6. **Address bias and calibration.**
   - Assessor training and calibration sessions
   - Frame-of-reference training
   - Multiple assessors per competency
   - Demographic-pattern monitoring (does evidence vary systematically by learner demographics?)

7. **Plan portfolio architecture.**
   - How evidence is captured, stored, retrieved
   - Learner-facing dashboard
   - Committee-facing rollup view
   - Audit trail for decisions

## False-Positive Prevention

| Common Mistake | Why It's Wrong | Correct Approach |
|---|---|---|
| Single-occasion observation for entrustment | Reliability suffers; one bad day misrepresents learner | Multiple observations across contexts |
| Knowledge test as competency evidence | Cognitive measure, not integrative performance | Triangulate with direct observation |
| Self-report as primary | Self-assessment unreliable, especially novice | Self-report is supplementary, not primary |
| Skipping authentic context | Simulation alone misses transfer | Authentic-context observation mandatory |
| Single rater | Halo effect, idiosyncratic bias | Multiple raters with calibration |
| No aggregation rule | Decisions made ad hoc, inconsistent | Explicit rule for evidence → decision |
| No bias monitoring | Demographic-pattern bias hidden | Monitor and surface patterns |
| Assessor capacity ignored | Plan fails on implementation | Compute assessor load and confirm feasibility |

## Verification Checklist

- [ ] Every competency has ≥3 evidence sources from different modalities
- [ ] Direct observation in authentic context for every competency
- [ ] Sampling frequency specified
- [ ] Every source tied to scoring tool
- [ ] Aggregation rule defined with decision-maker and cadence
- [ ] Calibration plan addresses assessor training and bias
- [ ] Portfolio workflow designed
- [ ] Assessor capacity confirmed
