# Signature Assignment Designer

**Objective:** Design a signature assignment — a course-embedded assessment that produces evidence of program-level student learning outcomes (PSLOs) — including the task specification, criterion-aligned rubric, scoring protocol, sampling plan, and traceability to PSLOs for program-assessment reporting.

## When to Use
- ✅ Designing course assignments that double as program-evidence sources
- ✅ Building a portfolio of signature assignments across the major
- ✅ Replacing course finals with PSLO-evidencing tasks
- ✅ Generating data for HLC/MSCHE/SACSCOC/WSCUC/NWCCU outcomes-assessment reporting
- ❌ Designing capstone (use `teaching_capstone_assessment_designer.md`)
- ❌ Auditing an existing rubric (use `teaching_rubric_alignment_to_outcomes.md`)

## Inputs Required
- **Course identity** (code, title, term position in major)
- **Target PSLO(s)** the assignment will evidence — with the depth (I/D/M) the course is supposed to contribute
- **Discipline-appropriate task formats** (research paper, project, performance, lab report, code project, clinical case, design)
- **Authentic-context constraints** (real audience, real problem, professional format)
- **Time and resource constraints** for students
- **Sampling plan:** census or sample for program reporting

## Constraints

**Must:**
- Task design must produce evidence at the PSLO's depth (M-depth assignments require demonstration of mastery)
- Rubric criteria align directly to PSLO elements; no generic-quality criteria dominating
- Scoring protocol specifies inter-rater calibration approach
- Sampling plan specifies how artifacts get to program assessment
- Authentic context (real audience, real problem) preferred over fabricated
- Assignment integrity addressed (AI-resistant or AI-transparent design)

**Must Not:**
- Use generic-quality rubric (grammar, organization) as primary criteria when PSLO is disciplinary
- Generate an assignment so resource-intensive that course faculty resist using it
- Skip the program-reporting workflow (assignment produced but never routed)
- Treat course grade as PSLO evidence (signature assignment score must be separately recorded with rubric)
- Design without considering integrity in AI context

## Instructions

1. **Confirm course and PSLOs.** Echo course identity, PSLOs targeted, depth contribution.

2. **Design the task.**
   - **Goal** (what students must accomplish)
   - **Role** (their stance — researcher, designer, analyst, practitioner)
   - **Audience** (real or simulated authentic audience)
   - **Situation** (the context)
   - **Product/Performance** (deliverable format)
   - **Standards for success** (links to rubric)

3. **Calibrate task complexity to PSLO depth.**
   - For Master-depth: task must require independent demonstration with authentic complexity
   - For Developed-depth: task may include scaffolding; complexity moderate
   - For Introduced-depth: rarely needs to be a signature assignment

4. **Design the rubric.**
   - Criteria map directly to PSLO elements (use the PSLO's component dimensions)
   - 3-4 performance levels
   - Each level has specific observable descriptors (not synonyms)
   - Parallel structure across levels

5. **Specify scoring protocol.**
   - Who scores (course instructor only / instructor + program assessor / external reviewer)
   - Calibration approach (anchor papers, frame-of-reference training, dual scoring with reconciliation)
   - When scoring occurs (during course grading / after course / annual review)

6. **Specify sampling plan.**
   - Census: all students' artifacts collected
   - Sample: which students (random, stratified by demographics, etc.)
   - Sample size for reliability
   - Storage and retrieval mechanism

7. **Design for integrity in AI context.**
   - In-class components (oral defense, presentation, in-class drafting)
   - Process evidence (drafts, brainstorming artifacts, peer reviews)
   - Personalization (require integration of student-specific data or experience)
   - Iterative production (multiple submissions with feedback)
   - Transparent AI policy (when and how AI use is permitted, must be disclosed)

8. **Build the traceability documentation.**
   - PSLO → rubric criterion mapping
   - Rubric criterion → task element mapping
   - Reporting template for program-assessment cycle

## False-Positive Prevention

| Common Mistake | Why It's Wrong | Correct Approach |
|---|---|---|
| Generic-quality rubric dominates | Doesn't produce PSLO signal | PSLO-aligned criteria are primary; mechanics secondary |
| Course grade as PSLO evidence | Grades aggregate too many factors | Score signature assignment with rubric, record separately from grade |
| No scorer calibration | Inter-rater reliability suffers | Anchor papers + calibration session before scoring |
| Fabricated context | Loses authenticity benefit | Real audience or simulated-real with named purpose |
| Resource-intensive design | Faculty resist; assignment becomes ceremonial | Right-size for the course context |
| No integrity design | AI-era contamination | Build in-class components, process evidence, personalization |
| No reporting workflow | Data collected but unused | Build the routing path explicitly |
| Sample too small | Unreliable for program decisions | Power analysis or census |
