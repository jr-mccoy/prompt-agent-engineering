# Logic Model & Theory of Change Designer

**Objective:** Design a complete logic model or theory of change for a program — sequencing inputs / activities / outputs / short-, mid-, and long-term outcomes; surfacing assumptions and external factors; specifying indicators for each outcome level; and producing a visual + narrative artifact suitable for funders, evaluators, and internal use.

## When to Use
- ✅ Grant proposal evaluation plans
- ✅ Program design or redesign
- ✅ Articulating program purpose for new staff or stakeholders
- ✅ Foundation of an evaluation framework
- ❌ Building the full evaluation framework (use `teaching_program_evaluation_framework.md`)
- ❌ PDSA cycle design (use `teaching_continuous_improvement_cycle.md`)

## Inputs Required
- **Program identity and population served**
- **Approach:** standard logic model / theory of change (more emphasis on assumptions and pathway)
- **Long-term outcome / impact** the program seeks
- **Available resources / inputs**
- **Planned activities**
- **External factors** that could moderate outcomes

## Constraints

**Must:**
- Specify inputs, activities, outputs, short-term outcomes (knowledge/skills/attitudes typical), mid-term outcomes (behavior/practice), long-term outcomes (status/condition)
- Surface assumptions explicitly between elements (e.g., "if X happens, then Y will follow because…")
- Specify indicators for each outcome level
- Document external factors / contextual moderators
- For theory of change: emphasize the pathway logic and preconditions
- Distinguish what the program directly controls (outputs) from what it influences (outcomes)

**Must Not:**
- Conflate outputs (what we produce) with outcomes (what changes)
- Skip assumptions (where most logic models fail)
- Claim direct control over long-term outcomes the program only contributes to
- Generate indicators that are aspirational rather than measurable
- Skip external factors

## Instructions

1. **Confirm inputs.** Echo program, population, long-term outcome, approach.

2. **Start from the long-term outcome.** Work backward.

3. **Define preconditions / mid-term outcomes.** What must change in behavior, practice, or knowledge for the long-term outcome to occur?

4. **Define short-term outcomes.** What knowledge, skills, attitudes, awareness must develop for mid-term to follow?

5. **Define outputs.** What does the program produce directly (events held, participants served, products developed)?

6. **Define activities.** What does the program do (teach, coach, design, recruit, evaluate, communicate)?

7. **Define inputs.** What resources go in (people, money, materials, time, expertise, partnerships)?

8. **Surface assumptions.** Between each adjacent element, state the assumption that connects them. Where assumptions are weak or contested, flag for testing.

9. **Specify indicators.** For each outcome level, name 1-3 indicators (measurable signals of change).

10. **Document external factors.** Conditions outside the program's control that could moderate outcomes (policy changes, labor market, demographic shifts).

11. **Audit.**
    - Outputs distinguished from outcomes
    - Assumptions surfaced at every link
    - Indicators measurable
    - External factors named
    - Pathway logic coherent

## False-Positive Prevention

| Common Mistake | Why It's Wrong | Correct Approach |
|---|---|---|
| Confusing outputs with outcomes | Misleads stakeholders about impact | Outputs = what we produce; outcomes = what changes |
| Skipping assumptions | Most logic-model failures hide in unsurfaced assumptions | State assumptions explicitly; rate evidence strength |
| Claiming control over long-term outcomes | Programs influence; rarely control | Frame as "contributes to," "increases probability of" |
| Aspirational indicators | Can't measure "transformed lives" | Specify observable, measurable signals |
| No external factors | Ignores reality | Name factors that could moderate impact |
| Same indicator at every level | Outcomes at different time scales need different indicators | Match indicator to outcome level |
| Visual without narrative | Visual alone misses the pathway logic | Pair model with narrative |

## Verification Checklist

- [ ] All six elements specified (inputs through long-term outcomes)
- [ ] Outputs distinguished from outcomes
- [ ] Assumptions at every link
- [ ] Indicators measurable at each outcome level
- [ ] External factors named
- [ ] Pathway logic coherent
- [ ] Visual + narrative
