# Student Choice Board / HyperDoc Designer

## Objective

Design a single-page or one-link choice board (often called a HyperDoc) that gives students multiple paths to the same learning objective. Output includes the objective, the choice grid (3×3 / 2×3 or "must-do + may-do + challenge"), task scaffolds, evidence requirements, and a teacher monitoring plan.

## When to Use

- Differentiating practice for a single objective across a wide range of readiness, interest, or modality preferences
- Sub-day plan with rich student agency
- Station rotation / blended block in a 1:1 or shared device classroom
- Project-week menu with required and optional artifacts
- Voice-and-choice unit closure

## When NOT to Use

- Single-task lesson with one correct path — use `teaching_lesson_plan_generator.md`
- Major project requiring multi-week scaffolding — design as project, not choice board
- Pure assessment — choice boards are for practice/synthesis, not for grading variation that obscures evidence

## Instructions

### Step 1: Anchor on One Objective

Choice boards lose coherence when they try to address multiple objectives. State one measurable outcome. All tasks on the board must serve it.

If you have multiple objectives, build multiple boards or sequence them.

### Step 2: Choose a Board Structure

Common patterns:

| Structure | Best for |
|-----------|----------|
| 3×3 tic-tac-toe (pick 3 in a row) | Encouraging variety across modality types |
| 3×3 free choice (pick N) | Maximum agency |
| Must-Do + May-Do + Challenge tiers | Coverage + differentiation + extension |
| Bingo board (pick N until "bingo") | Younger students, gamified |
| Pathway / branching | Skill-builds-on-skill content |

### Step 3: Design the Tasks

For each task, write:

- Task title (active verb)
- One-sentence task summary
- Materials / resources needed
- Estimated time
- Evidence required (what student turns in / shows)
- Differentiation level / type (readiness, interest, modality)
- Tech requirement
- Scaffold available (yes/no, link)

Use a mix across:
- Cognitive demand (recall → application → analysis → creation)
- Modality (read, watch, listen, build, draw, speak, write, code)
- Social structure (solo, pair, small group)
- Output format (written, visual, oral, performance, build)

### Step 4: Cover the Modality / Demand Matrix

A quick check: do tasks span this matrix?

| Demand → / Modality ↓ | Recall | Apply | Analyze | Create |
|-----------------------|--------|-------|---------|--------|
| Read | | | | |
| Watch | | | | |
| Build / make | | | | |
| Discuss / oral | | | | |
| Write | | | | |
| Visual / draw | | | | |

You don't need every cell filled; you should not have all tasks in one row or column.

### Step 5: Define "Must-Do" Floor

Even with choice, ensure baseline coverage. Specify:

- 1–2 Must-Do tasks every student does (the spine of the objective)
- 2–4 May-Do options (variation)
- 1–2 Challenge / extension options (for stretch)

This protects the objective while still offering agency.

### Step 6: Build Scaffolds Per Task

For tasks where students might struggle:

- Sentence starters
- Vocabulary support
- Worked example / model
- Graphic organizer
- Translation / language scaffold
- Audio / read-aloud option
- Peer support pathway
- Teacher conference flag

Tag which tasks have scaffolds; don't expect every student to know they exist.

### Step 7: Evidence & Submission Plan

For each task, specify what evidence the teacher will see:

- Submitted artifact (where, format)
- Live observation (when teacher checks in)
- Peer review or share-out
- Self-assessment

If a task has no evidence, the teacher can't tell whether learning happened.

### Step 8: Teacher Monitoring & Conferring Plan

The hidden failure mode: the teacher disengages because students are "all working." Plan:

- Clipboard or doc with student names + task taken
- Conferring schedule (3–5 min per student, prioritized)
- Checkpoints at start, mid, end
- Quick formative reads (exit ticket, share-out, self-rating)

Without this, choice = drift.

### Step 9: Tech / Logistics Logistics

- Single link or printed sheet?
- Submission method (LMS, shared folder, paper)?
- Materials station setup
- Grouping flexibility (some tasks pair-only, some solo)
- Noise / movement norms during the block

### Step 10: Accessibility

- [ ] Multiple modalities present (reading-only is not accessible to all)
- [ ] Audio / video has captions / transcript
- [ ] Reading level scaffolded for ELL / SpEd
- [ ] Tech tasks have low-tech alternatives where needed
- [ ] Color is not the sole way to navigate the board
- [ ] Tasks don't presume cultural / economic context students may not share

### Step 11: Closure & Synthesis

After tasks are done:

- Whole-class share-out: 2–3 students show evidence
- Synthesis: what we learned, common confusions
- Connection to next lesson
- Reflection prompt (which task did you choose, what did you learn, what would you choose next time?)

## Output Format

1. Single learning objective (measurable)
2. Board structure choice with rationale
3. Per-task spec (title, summary, evidence, time, differentiation tag)
4. Modality/demand coverage matrix
5. Must-Do / May-Do / Challenge tier map
6. Scaffolds per task
7. Evidence & submission plan
8. Teacher monitoring & conferring plan
9. Tech / logistics plan
10. Accessibility audit
11. Closure & synthesis plan

---

## False-Positive Prevention

❌ **DON'T:**
- Stack tasks across multiple objectives — focus blurs
- Make every task a worksheet — modality variety is the point
- Skip the must-do floor — agency without coverage drifts
- Hand out a board and disengage — teacher monitoring is mandatory
- Assume tech access — provide low-tech paths
- Forget evidence — an artifact-less task can't show learning

✅ **DO:**
- Anchor on one objective
- Span the modality/demand matrix
- Specify a must-do floor
- Build conferring into the block
- Provide scaffolds and accessibility paths
- Close with synthesis

## Quality Indicators

- [ ] One objective; all tasks aligned
- [ ] Mix of modalities and cognitive demands
- [ ] Must-do floor + variation + extension
- [ ] Each task has evidence requirement
- [ ] Conferring schedule planned
- [ ] Accessibility checks pass
