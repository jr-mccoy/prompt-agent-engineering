# Common Formative Assessment for PLC

## Objective

Produce a complete CFA package for a PLC (professional learning community): the targeted essential standard, an item bank, a scoring/calibration agreement, a data-meeting protocol, and tiered instructional responses keyed to results. Output is what a grade-level or course-alike team needs to actually run a CFA cycle, not just administer a quiz.

## When to Use

- Course-alike or grade-level PLC teams running data-driven cycles
- Replacing inert "common assessment" practice with genuine inquiry
- Onboarding new teachers to the PLC's CFA process
- Auditing a CFA system that has drifted into common-grading-without-common-instruction

## When NOT to Use

- Single-teacher classroom assessment — use `assessment_test_blueprint_table_of_specs.md`
- Calibration of writers across a stack — use `assessment_anchor_paper_exemplar_generator.md`
- Diagnosing a misconception in a single student — use `teaching_misconception_diagnoser.md`

## Instructions

### Step 1: Define the Essential Standard Sharply

Convert the standard into specifics:

```
STANDARD: [Code + text]

WHAT STUDENTS WILL DO TO SHOW MASTERY: [Behavior-specific. Bad: "understand X." Good: "use a model to explain how X causes Y."]

THE COGNITIVE DEMAND: [DOK 1 / 2 / 3 — and why]

WHAT MASTERY LOOKS LIKE: [One-sentence description of "got it"]
WHAT NOT-YET-MASTERY LOOKS LIKE: [Common partial pattern]
```

If team members would describe the standard differently, the CFA is already broken. Settle this in Step 1.

### Step 2: Item Bank

Build 4–8 items at the appropriate DOK. Each item:

- Targets the standard (no extraneous content that confounds interpretation)
- Distinguishes mastery from partial — design around predicted misconceptions
- Is short enough to fit the admin window
- Has parallel forms (Form A / Form B) so adjacent classes can use different versions

Item types to consider:

| Type | When useful |
|------|-------------|
| Constructed-response | When reasoning matters |
| MC with diagnostic distractors | When efficiency + diagnostic info both needed |
| Short performance task | When standard is procedural or applied |
| Two-part item (answer + justification) | When you want both correctness and reasoning data |

Output:

| Item | DOK | Targets which sub-component | Predicted misconception in distractors / common error |

### Step 3: Scoring Agreement

The PLC must score the same way. Provide:

- A 0–4 (or 0–3) scale per item, with **descriptors** of what each level looks like
- Anchor responses (real or generated) at each level
- A calibration protocol: team members independently score 5–10 sample responses, compare, discuss disagreements before scoring the full set

Disagreements among graders signal unclear descriptors — revise before scoring.

### Step 4: Administration Protocol

Specify:

- Administer within an agreed window (e.g., this week, all sections)
- Conditions: open / closed notes; calculator / no calculator; time
- Anti-coaching: teachers don't reteach right before; students don't preview items
- Make-up procedure for absentees

### Step 5: Data Display Template

Build the data display the team will look at together:

| Standard | Item | Class A %M | Class B %M | Class C %M | Team total %M | Misconception flag |
|----------|------|-----------|-----------|-----------|---------------|-------------------|

Where %M = percent at mastery; flag any cell below team-agreed threshold (commonly 70–80%).

Also build student-level grouping:

| Student | Item 1 | Item 2 | Item 3 | Pattern |
|---------|--------|--------|--------|---------|

Use this to identify students for tier 2 / tier 3 response.

### Step 6: Data-Meeting Protocol

The 30–45 minute meeting protocol:

```
0–5 min: Set norms; clarify the question being answered.

5–15 min: Look at the data without explaining it yet.
"What do we notice?" "What surprises us?"

15–25 min: Hypothesize the why.
"Where do students seem stuck?"
"What might explain class-to-class differences?"
"What might we have under-taught?"

25–40 min: Decide the response.
- Whole-class re-teach: which item / misconception?
- Small-group re-teach: which students by which pattern?
- Tier-2 referral: who needs more than re-teach?
- Curriculum revision: what to change next time we teach this?

40–45 min: Name commitments.
"By [date], we will each ___."
```

The protocol must always end with named commitments. Otherwise data review is performative.

### Step 7: Tiered Response

For each common pattern surfaced, the team plans:

| Pattern | Tier 1 (whole-class) | Tier 2 (small group) | Tier 3 (intensive) |
|---------|---------------------|--------------------|--------------------|
| [Misconception A] | [10-min re-teach lesson] | [Targeted strategy + practice] | [Referral + diagnostic] |

Output 1–2 tier-1 re-teach lessons fully sketched (objective, sequence, exit) so the team can deploy them this week.

### Step 8: Re-Test Plan

Plan the re-assessment:

- When (within 1–2 weeks of the original)
- What (parallel form or specific items)
- For whom (students below threshold)
- How recorded (most-recent if SBG; gradebook policy specified)

### Step 9: Equity Look

Disaggregate where ethically appropriate and useful:

- Are there patterns by class section that suggest instructional variance?
- Are there subgroups where mastery rates differ markedly?
- Is the difference an instruction issue or an item-bias issue?

Frame as inquiry, not blame. Use to drive equity conversations in the PLC.

### Step 10: Self-Check

- [ ] Is the standard defined sharply enough that the team agrees on mastery?
- [ ] Does the item bank distinguish mastery from partial?
- [ ] Is scoring calibrated before grading the full set?
- [ ] Does the data-meeting protocol end with commitments?
- [ ] Is the tiered response specific, not vague?
- [ ] Is the re-test plan documented?

## False-Positive Prevention

❌ **DON'T:**
- Treat CFA as common-test-administered, period — that's not the cycle
- Score without team calibration on anchor responses
- End the data meeting without named commitments
- Confound common assessment with common instruction (CFA reveals; instruction can still vary)
- Disaggregate without an equity-inquiry frame

✅ **DO:**
- Define the standard so all team members would score the same way
- Build distractors / items that surface specific misconceptions
- Calibrate before scoring the full set
- End data meetings with commitments and a re-test plan
- Use disaggregation as inquiry, not judgment

## Quality Indicators

- [ ] Standard defined with mastery and not-yet-mastery descriptions
- [ ] Items target standard with diagnostic value
- [ ] Scoring calibrated before stack-grading
- [ ] Data meeting ends with named commitments
- [ ] Tiered response includes a specific re-teach plan
- [ ] Re-test plan documented
- [ ] Equity look frames inquiry, not blame
