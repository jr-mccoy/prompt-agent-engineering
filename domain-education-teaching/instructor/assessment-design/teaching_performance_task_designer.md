# Performance Task Designer

## Objective

Design a complete performance task — Goal, Role, Audience, Situation, Product, Standards (GRASPS) — that requires students to apply targeted standards in a novel context. Output includes student-facing prompt, multi-day workflow, scaffolds, analytic rubric, and proficient-level exemplar.

## When to Use

- Summative assessment of transfer (not recall)
- Anchor task for a UbD-style unit
- Capstones, exhibitions, defenses
- Replacing tests for standards that require demonstration over selection

## When NOT to Use

- Recall / fluency assessment — use MC items
- Multi-week project — use `teaching_project_based_learning_designer.md`
- Single-skill rubric only — use `teaching_assessment_rubric_builder.md`

## Instructions

### Step 1: Define Transfer Goal

State what students must do that proves transfer:

> **Students can [verb at DOK 3–4] [content/skill] in [novel context] to produce [authentic product] for [authentic audience].**

If the task can be completed by recalling a procedure or producing a familiar form, redesign for transfer.

### Step 2: GRASPS Frame

Build the task using GRASPS:

| Element | Definition | Your task |
|---------|-----------|-----------|
| **Goal** | What students must accomplish (purpose) | |
| **Role** | Who students are in the task | |
| **Audience** | Who the product is for (real if possible) | |
| **Situation** | The context / scenario | |
| **Product** | What students produce | |
| **Standards** | Success criteria (criteria, not just checklist) | |

If audience is fictional, name a plausible real audience the work could reach.

### Step 3: Standards Alignment

| Standard / objective | How task assesses it | DOK |
|---------------------|---------------------|-----|

Each standard must be assessable from the product or process — not assumed.

### Step 4: Student-Facing Task Prompt

Write the task as students will receive it. Include:

```
[TITLE]

The Situation:
[2–4 sentence narrative — sets context, hooks interest]

Your Role:
[Role and authority]

Your Audience:
[Who you're producing this for and why they care]

Your Goal:
[What you must accomplish]

Your Product:
[Specifications — format, length, components, quality bar]

Constraints:
- [Limit 1]
- [Limit 2]

Resources you may use:
- [List]

What success looks like:
[Plain-language criteria — translates the rubric]
```

### Step 5: Multi-Day Workflow

For tasks ≥2 days, build the workflow:

| Day | Phase | Student work | Teacher moves | Checkpoint |
|-----|-------|-------------|---------------|------------|
| 1 | Launch + plan | Read prompt, ask questions, plan | Norm prompt, model planning | Plan submitted |
| 2 | Draft / produce | Build core of product | Confer | Draft check |
| 3 | Critique + revise | Peer feedback | Facilitate critique protocol | Revision plan |
| 4 | Finalize + submit | Complete + reflect | Collect | Final + reflection |

### Step 6: Analytic Rubric

Build a 3- to 5-criterion analytic rubric. For each criterion:

| Criterion | 4 Exemplary | 3 Proficient | 2 Developing | 1 Beginning |
|-----------|-------------|--------------|--------------|-------------|

Criteria rules:
- Each criterion targets a different standard or skill
- Descriptors are observable in the product, not in effort
- Proficient = standards met; exemplary = exceeded with sophistication
- Avoid double-jeopardy (penalizing the same flaw under two criteria)

Include a **process** vs. **product** split if process matters (e.g., research process vs. final paper).

### Step 7: Proficient Exemplar

Produce a proficient-level exemplar response. Show enough of the actual product (or detailed description) that a teacher could norm scoring against it. If the product is multi-modal, describe each component.

State explicitly: "This exemplar would score 3 on every rubric criterion."

### Step 8: Scaffolds and Differentiation

| Need | Scaffold |
|------|----------|
| Below-level reader | Audio of prompt, glossed terms, partial outline option |
| ELL | Visual storyboard before drafting, sentence frames in product |
| IEP — extended time | Extra day, broken submission gates |
| Above-level | Stretch criterion (e.g., "addresses a counterargument") or audience expansion |

### Step 9: Logistics & Equity Check

- [ ] All students have access to required tech/materials
- [ ] Group composition (if group task) accounts for skill mix and social dynamics
- [ ] No assumed cultural references that exclude students
- [ ] Audience selection doesn't expose students to harm (privacy, vulnerability)
- [ ] Submission method is accessible (multiple formats accepted)

### Step 10: Companion Outputs

Produce:
- Student-facing prompt (clean, single page)
- Rubric (single page, student-friendly version + teacher version if different)
- Workflow timeline
- Exemplar (with norming notes)
- Reflection prompt for students post-submission

## False-Positive Prevention

❌ **DON'T:**
- Design a task that can be completed from memory or template
- Score effort instead of product quality
- Stack rubric criteria so the same flaw is penalized twice
- Use a fictional audience when a real one is available
- Skip the exemplar — teachers can't norm without one

✅ **DO:**
- Require transfer to a novel context
- Tie every rubric criterion to a different standard
- Provide a proficient exemplar
- Build in critique and revision before final submission
- Audit equity before launch

---

## Quality Indicators

- [ ] Task requires transfer, not recall or recognition
- [ ] GRASPS elements all present and authentic
- [ ] Every standard maps to a rubric criterion
- [ ] Rubric descriptors are observable, not effort-based
- [ ] Exemplar provided and explicitly norm-scored
- [ ] Equity audit completed
