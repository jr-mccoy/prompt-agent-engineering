# Microlearning Module Designer (5–15 min)

## Objective

Produce a single 5–15 minute microlearning unit that a busy learner can finish in one sitting and apply within 24 hours. One skill, one concept, one practice rep, one transfer cue. Output is the script, on-screen text, embedded check, and a printable job-aid card.

## When to Use

- Skill refresh between major training events
- Rolling out a single policy/tool change
- Reinforcing a behavior already taught in a longer course
- Onboarding "day one" reminders
- Pre-training warm-up or post-training booster

## When NOT to Use

- Foundational skill — needs more than 15 minutes; use `hecorp_async_lms_module_designer.md`
- Multi-step process — break into a series of micro modules
- Compliance with audit trail requirements — use `hecorp_compliance_training_module.md`
- At-the-moment-of-need quick reference — use `hecorp_performance_support_job_aid.md`

## Instructions

### Step 1: Squeeze the Outcome to One Sentence

Format: "After this, learner can [observable action] when [trigger] so that [business or learner result]."

If you can't squeeze it to one sentence, the module is too big — split it.

### Step 2: Time Budget Allocation

For a 10-minute module (default):

| Segment | Time | Purpose |
|---------|------|---------|
| Hook | 0:30–1:00 | Why this matters now |
| Concept | 2:00–3:00 | One model / rule / decision |
| Worked example | 1:30–2:00 | Apply the concept once |
| Practice rep | 2:00–3:00 | Learner does, gets feedback |
| Job aid + transfer cue | 1:00 | Take-away artifact + when to use |
| Check + close | 1:00 | One question + commitment |

Adjust proportionally for 5- or 15-minute versions.

### Step 3: Hook (the first 30–60 seconds)

The hook earns the next 9 minutes. Choose one:
- A specific recent failure mode ("Last quarter, X happened in Y% of calls")
- A learner-voice quote ("I never know what to say when...")
- A surprising fact tied to outcome
- A concrete scenario the learner will recognize

Avoid: organizational throat-clearing, learning-objective recital, generic "in this module..."

### Step 4: One Concept, One Mental Model

State the single take-away as a:
- Rule (if X, then Y)
- 3-step process (memorable, not 7)
- Decision tree (≤3 branches)
- Heuristic ("when in doubt, do Z")

Show it visually if delivery format allows. Keep on-screen text under 25 words per slide/segment.

### Step 5: Worked Example

Walk through one concrete application. Narrate the decision points. Stay in one scenario — don't show three.

### Step 6: Practice Rep With Feedback

Learner does, not watches. One of:
- Multiple-choice scenario with reasoned feedback per option
- Open response with auto-feedback rules ("If you wrote X, consider Y")
- Drag/sort if delivery format supports it
- Scenario branching (one or two decisions, not five)

Provide feedback that names *why*, not just right/wrong.

### Step 7: Job Aid + Transfer Cue

Output a printable / mobile-savable card the learner keeps:
- One-page (or one-screen) summary
- The mental model from Step 4
- A "when to use this" cue
- A "first time you use this" reflection prompt

This is what makes microlearning transfer rather than evaporate.

### Step 8: Check + Commitment Close

End with:
- One quick check (single MC or fill-in tied to the outcome)
- A specific commitment prompt: "In the next 24 hours, I will use this when ___"

### Step 9: Reinforcement Plan

Microlearning alone usually doesn't stick. Pair with at least one of:
- Manager prompt to ask about it in 1:1
- Spaced booster 2–7 days later (one question)
- Performance-support card available at the moment of need
- Practice opportunity scheduled within 1 week

### Step 10: Production Specs

For the chosen delivery format, output:

- **Script** — what is said, with timestamps
- **On-screen text** — exact words, line breaks
- **Visuals** — describe each (or note "instructor headshot only")
- **Interactions** — exact wording of prompts and feedback
- **Job aid file** — content for the take-away card
- **Accessibility** — captions, alt text, reading level

### Step 11: Time-Budget Audit

Read aloud to confirm actual runtime. Cut or compress until the segment fits the time budget. The most common failure mode is overstuffing — protect the budget.

## Output Format

1. One-sentence outcome statement
2. Time budget allocation table
3. Hook (script + visual)
4. Concept / mental model (script + visual)
5. Worked example (script + visual)
6. Practice rep with feedback rules
7. Job aid card (paste-ready)
8. Check question + commitment prompt
9. Reinforcement plan
10. Production specs (script, on-screen text, accessibility)
11. Time-budget audit confirming runtime

---

## False-Positive Prevention

❌ **DON'T:**
- Try to teach two skills in one micro module
- Open with the learning objective recited
- Skip the practice rep — passive micro is just a video
- Forget the job aid — micro without artifact rarely transfers
- Let the script bloat past the time budget

✅ **DO:**
- Squeeze to one outcome
- Hook with specific, concrete relevance
- Build one practice rep with feedback rules
- Hand the learner an artifact
- Pair with reinforcement — micro is a node, not a system

- [ ] Outcome stated in one sentence
