# Roadmap

Productization plan for **Prompt & Agent Engineering (PAE)**.

**No dates.** Nothing here is scheduled; the ordering reflects dependencies, not
commitments. **No benchmark results are claimed anywhere in this repository**,
because none have been run yet. When they are, they will ship with a
reproducible harness and the numbers will live in generated artifacts, not prose.

Architecture context: [`ARCHITECTURE.md`](ARCHITECTURE.md). Settled decisions:
[`meta/adr/`](meta/adr/).

---

## Current

Available today, exercised by CI:

- **A governed resource corpus** — prompts, techniques, skills, agents,
  commands, personas, authoring systems, and self-contained toolkits. Counts and
  their membership rules: [`meta/REPOSITORY_FACTS.json`](meta/REPOSITORY_FACTS.json).
- **A machine-readable prompt index** — `PROMPT_INDEX.json`, regenerated by
  `scripts/generate_prompt_index.py` and verified current in CI.
- **A formal technique catalog** — `techniques/MASTER_TECHNIQUE_INDEX.md`, with
  deprecation stubs, merge records, and an integrity auditor.
- **Authoring systems** for prompts, skills, agents, commands, and whole agentic
  systems, with quality rubrics.
- **A validation suite** — index freshness, inventory counts, technique
  integrity, naming conventions, body-link resolution, frontmatter
  cross-references, vendored-copy drift, reorg-map application, structure gate,
  and toolkit unit tests.
- **A generated-facts control plane** — every published repository count is
  generated, declared in a machine-readable marker, and CI-verified.
- **Documentation routing** — one canonical routing reference (`CLAUDE.md`) with
  thin bootstraps pointing at it.

Not available: any executable engine. There is no `pae` command, no search, no
routing code, no MCP server, no context compiler, and no evaluation harness.

## Next

The immediate productization work, roughly in dependency order.

1. **Registry schema and resource identity.** Define the normalized resource
   record and a stable ID scheme that does not depend on path, filename, or
   title. Persist IDs so they survive file moves; resolve historical paths
   through aliases derived from `meta/REORG_MAP.tsv`, keeping
   identity-preserving moves distinct from `superseded-by` / `merged-into`
   redirects. ID collisions are fatal at generation time.
2. **Kind detection and membership boundary.** Decide by resource *shape*, not
   location, so the agents, skills, and commands that live outside
   `domain-agentic-resources/` are classified correctly, and bundled component
   files are modeled as attachments rather than resources.
3. **Resource-kind adapters.** One loader per native frontmatter shape emitting
   the common registry schema. The corpus keeps its existing formats.
4. **Sidecar metadata** under `meta/registry/` — maturity, review status,
   evaluation status, license, attribution, provenance, canonical/copy
   relations, serving policy. Required because byte-identical vendored resources
   cannot be edited to carry project metadata.
5. **Machine-readable techniques**, generated by reusing the existing
   `techniques/audit_technique_index.py` parser rather than writing a second one.
6. **Licensing and attribution in the registry contract**, so anything served
   later carries its upstream license and pinned source revision.
7. **Cross-reference debt reduction** — shrink `meta/xref_baseline.json`
   deliberately, in reviewable batches, never by mass rewrite.

## Later

Sequenced after the registry exists.

- **`pae-engine/` package** — conventional Python layout, dependency-light
  offline-capable core, optional extras for MCP / evaluation / tokenizers.
- **Deterministic search** — metadata filters, IDs, and structural queries that
  need no model call.
- **Task routing and ranked retrieval** over registry metadata.
- **Token-budgeted context compilation**, with a serving-policy gate that
  refuses to emit a bundle rather than silently truncate required safety
  material out of a safety-gated resource.
- **Executable routing.** `pae route` becomes canonical; `CLAUDE.md` and the
  other client bootstraps shrink to point at it, keeping a documented fallback
  for environments without the CLI. The executable router and any generated
  routing documentation derive from the same metadata.
- **Read-only MCP surface** — `search_resources`, `get_resource`, `route_task`,
  `compose_bundle`, `validate_resource`. The MCP layer calls the same engine
  functions as the CLI. `get_resource` and `compose_bundle` enforce serving
  policy. Retrieved content stays data and never gains authority by containing
  imperative text.
- **Evaluation.** A reproducible harness comparing at least three conditions —
  baseline, raw repository, and PAE-assisted — across routing accuracy, context
  size, latency, deterministic task checks, and safety-boundary compliance.
  Independently versioned suites (e.g. `routing-v1`).
- **Security regression testing**, including adversarial resources.
- **Case studies** drawn from real runs, not illustrations.
- **Releases.** The repository has no tags and no released version; the first
  public product release may begin at `0.1.0`. Preferred distribution name
  `prompt-agent-engineering` (available on PyPI at the time of checking);
  preferred import namespace and CLI `pae` — note the top-level import name
  `pae` is already taken on PyPI by an unrelated package, an accepted and
  recorded risk. `continuity-kit` keeps its own package version. Registry schema
  and benchmark suites version independently of the distribution.

---

## Explicit non-goals

PAE is not a hosted model provider, an autonomous code-execution platform, a
replacement for model/system/user instructions, or a mechanism for silently
executing instructions found in retrieved content. It does not claim every
resource in the corpus is production-grade, and productization will not require
rewriting the existing corpus.
