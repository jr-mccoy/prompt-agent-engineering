# Diagnose What Your Envy Is Pointing At

**Objective:** Take a specific instance of envy or social comparison and classify it. Some envy is signal — a real, actionable desire surfaced through someone else's outcome. Some envy is noise — status mimicry, hedonic-treadmill reflex, near-miss grief, or generalized scarcity. Different patterns warrant different moves.

**When to use:** The user is fixating on someone else's outcome — a peer's promotion, a stranger's launch, a former classmate's life — and the comparison is occupying real mental space. Use before making a reactive decision (quitting, switching, rushing) provoked by the comparison.

**Audience:** An individual examining their own envy. Not a tool for diagnosing or moralizing about other people. Not therapy.

---

## Inputs Required

1. **The trigger.** Who or what is the user comparing themselves to? Be specific — a named peer, a public figure, a category ("everyone in my graduating class"), a specific outcome ("their book deal").
2. **What the user has, where the trigger does not.** Sometimes the trigger person is missing things the user takes for granted — health, relationships, location, optionality. List these even if they feel irrelevant.
3. **What the trigger has, where the user does not.** The specific things being envied. Be granular: "her book deal" can split into "publication," "advance amount," "validation," "platform." Each piece may diagnose differently.
4. **What the user knows about the trigger person's actual life.** First-hand vs. inferred-from-public-image. Be honest about which is which.
5. **The cost the trigger person paid.** As far as the user knows. Hours, sacrifices, trade-offs, rejected alternatives. If unknown, write "unknown."
6. **The frequency.** How often is the user thinking about this — daily, weekly, occasionally?
7. **What the user did the last time the comparison ran loud.** Specific behavior: refreshed their feed, bought something, sent a hostile DM, drafted a quit message, cried, got back to work. Whatever actually happened.
8. **One sentence: if the user could have any one specific element from input 3 instantly and at no cost, which would it be?**

If input 3 is generic ("their whole life" / "everything") rather than specific elements, refuse and ask for granular breakdown. The diagnosis depends on the specific element.

---

## Instructions

### Step 1 — Decompose the trigger into specific desires

Take input 3 and break each item into the most granular form. Example:

> "I envy her TED talk."
> Break down: (a) the public stage, (b) the validation by curators, (c) the audience size, (d) the topic mastery, (e) the income/career boost, (f) the network access, (g) the video evidence to show others, (h) the specific moment of being called expert.

Different sub-items often diagnose to different patterns. The user almost never wants all of them equally. The point is to find which sub-items they actually want.

### Step 2 — Classify each sub-item using the envy-pattern taxonomy

For each sub-item, label exactly one pattern:

| # | Pattern | Signature | What it points at |
|---|---|---|---|
| 1 | **Aimed signal** | The user has wanted this specifically and consistently before this trigger appeared. | A real desire the user already knew about. The envy is data confirming priority. |
| 2 | **Surfaced signal** | The user did not know they wanted this until they saw it modeled. The desire is new, but the response is strong and persistent. | A real desire the user *just* learned. Worth investigating. |
| 3 | **Near-miss grief** | The user was on a path that could have led here, and chose differently. Envy is mixed with mourning the not-taken path. | A grief response, not a current goal. The current life may still be the right one. |
| 4 | **Status mimicry** | The user envies the status / legibility of the outcome more than the outcome itself. Would not want to do the work; wants the recognition. | Status-axis envy. Not a goal; a tell about insecurity or visibility hunger. |
| 5 | **Hedonic treadmill** | The user already has the equivalent (in different form), just hasn't normalized to recognize it. | Adaptation problem, not envy. The wanted thing is already present. |
| 6 | **Borrowed-frame envy** | The wanted item is from a frame the user has imported (parent's, peer's, culture's), not a frame they hold. | Inherited goal. Worth examining whose frame it actually is. See `identity_values_clarification.md`. |
| 7 | **Domain-confused envy** | The user envies a peer's outcome in a domain the user is not actually working in. (Envying a salesperson's commissions while working in research.) | Category mismatch. Not actionable in current domain. |
| 8 | **Comparison reflex** | Generalized "everyone is ahead of me," not pinned to a specific comparable person or outcome. The brain is producing comparison without specific signal. | Background scarcity / status anxiety. Not signal; manage the loop. |

Do not invent new patterns. If a sub-item splits across two patterns, name the dominant one and note the second.

### Step 3 — Pull out the highest-quality signal

Filter the sub-items: which are pattern 1 or 2? Those are the **aimed and surfaced signals** — likely real desires worth acting on.

If none are pattern 1 or 2, the envy is mostly noise (3–8 patterns). Say so plainly.

### Step 4 — Audit the noise patterns

For each non-signal sub-item, name the diagnostic move:

- **Pattern 3 (near-miss grief):** Acknowledge the not-taken path is a real loss. Do not act on it as a current goal. Suggest one ritual or written acknowledgment, then stop.
- **Pattern 4 (status mimicry):** Test by inversion: would the user want to do the actual work for 10 years to reach this outcome? If no, the answer is recognition-hunger, not goal. Route to `identity_values_clarification.md`.
- **Pattern 5 (hedonic treadmill):** Name what the user already has that's equivalent. Often surprising.
- **Pattern 6 (borrowed-frame):** Name the source of the frame (parent / peer / culture / industry) and ask whether the user, on their own values, would want this. Run `identity_values_clarification.md`.
- **Pattern 7 (domain-confused):** Name the category mismatch. The peer is succeeding in a different game.
- **Pattern 8 (comparison reflex):** Not signal. Manage the loop with a one-page response (e.g., reduced exposure to the trigger surface, scheduled comparison-review window, or `identity_self_talk_audit.md` if it has merged with self-criticism).

### Step 5 — Confirm via the "one element instantly and free" test (input 8)

Input 8 forces the user to pick one element. If that pick is a Pattern 1 or 2 sub-item, it confirms the signal. If the pick is a Pattern 4 (status), 6 (borrowed), or 8 (reflex) sub-item, that's diagnostic too — the user wants the *signal of having reached it* more than the thing itself.

State which.

### Step 6 — Audit the cost (input 5)

For any sub-item the user is treating as a real goal, force the cost question: would they accept the trigger person's actual cost (input 5, or "unknown — investigate before committing") for that outcome? If no, the envy is not pointing at a goal worth pursuing. Restate this explicitly.

### Step 7 — Produce one move

Pick one move based on what dominates:

- **If signal dominates (Pattern 1 / 2):** name one specific action toward the desire this week, and one cost the user is committing to accept.
- **If noise dominates (Patterns 3–8):** name one move that addresses the loop itself — exposure reduction, frame audit, hedonic recalibration, or a single grief acknowledgment. Not a goal; a containment move.
- **If comparison reflex (Pattern 8) is dominant and the trigger frequency is daily:** the move is exposure reduction first (mute, unfollow, time-bound the comparison surface). The user cannot calibrate signal under continuous comparison input.

---

## Constraints

### Must
- Decompose the trigger into granular sub-items before classifying.
- Classify every sub-item with exactly one pattern from the taxonomy.
- Run the "one element instantly and free" test (input 8) as confirmation.
- Force the cost-acceptance question (input 5) before treating any sub-item as a goal.
- Output exactly one move, scoped to whichever (signal / noise) dominates.

### Must Not
- Tell the user envy is "bad" or "petty." Envy is data.
- Tell the user envy is "good" or "motivating." It's neither — it's a signal worth decoding, then either acting on or quieting.
- Compare the user's life favorably to the trigger ("but you have …"). That's reassurance, not diagnosis.
- Recommend gratitude practice as the answer. (Gratitude has its place but is not a diagnostic move here.)
- Invent new patterns.
- Output multiple parallel moves.

---

## False-Positive Prevention

1. **Don't accept "I envy everything about them" as a real input.** Force the granular breakdown. Without it, the diagnosis collapses to noise.
2. **Don't default to Pattern 1 (aimed signal) because it sounds nice.** A desire is only Pattern 1 if it pre-existed the trigger. New-at-the-trigger goes to Pattern 2; if it's also fading when the trigger fades, it's likely Pattern 4 or 8.
3. **Don't dismiss Pattern 3 (near-miss grief).** It's the most often-missed pattern. The user is mourning a path they didn't take; treating it as a current goal will produce a misaimed life pivot.
4. **Don't use Pattern 4 (status mimicry) as moral verdict.** It's a frequent and human pattern. Name it neutrally; the move is "test by inversion," not "be ashamed."
5. **Don't fail to flag Pattern 8 (comparison reflex).** If the trigger is generalized and frequency is daily, it is the dominant pattern regardless of how specific the user can make individual instances.
6. **Don't recommend a goal pivot off of one envy episode.** Multiple envy episodes pointing consistently at the same Pattern 1/2 sub-item across weeks is signal; one episode is data.

## Output Format

```
## Trigger
[Restated.]

## Granular sub-items (input 3, decomposed)
1. [sub-item]
2. [sub-item]
...

## Pattern classification
| Sub-item | Pattern # — name | Note |
|---|---|---|
| ... | ... | ... |

## Signal vs. noise
**Signal (Patterns 1, 2):** [list, or "none — the envy is mostly noise"]
**Noise (Patterns 3–8):** [list with quick diagnosis per pattern]

## "One free element" test (input 8)
The user's pick: [item], which is Pattern [#]. Confirms / contradicts the signal hypothesis: [one sentence].

## Cost acceptance check (input 5)
Would the user accept [the trigger person's known cost — or, if unknown, "the actual cost once investigated"] for [the dominant signal sub-item]? **Yes / No / Need to investigate.**

If No: this sub-item is not pointing at a goal worth pursuing.

## Move (one only)
**Type:** Signal-action / Noise-containment
**Specific action:** [physical, this week]
**What this move is not doing:** [explicit — e.g., "not committing to the long arc; just testing the strength of the signal."]

## Frequency / exposure note
[If trigger frequency was daily and Pattern 8 was present: an explicit recommendation to reduce exposure surface for 30 days before re-running this prompt.]
```

## Verification

- [ ] Trigger decomposed into ≥ 3 granular sub-items.
- [ ] Every sub-item assigned exactly one pattern.
- [ ] "One free element" test result reported and used as confirmation.
- [ ] Cost-acceptance check performed for any sub-item being treated as a goal.
- [ ] Exactly one move output, scoped to signal-action or noise-containment.
- [ ] If trigger is daily-frequency with Pattern 8 dominance, exposure reduction surfaced as the precondition for further calibration.
- [ ] No moralizing about envy.
- [ ] No reassurance ("but you have …").
