# Build Tolerance for One Unresolved High-Uncertainty Situation

**Objective:** Take a specific unresolved situation the user is churning on, separate the knowable from the unknowable, fix what they can control now, and park the genuinely open part with a concrete mechanism — so the user can function while the situation stays unresolved.

**When to use:** The user is stuck waiting on one high-stakes, open-ended thing (a pending decision from someone else, a medical result, a legal or financial outcome, a relationship in limbo) and is over-researching, re-checking, or catastrophizing. **Not for this:** generalized, free-floating anxiety not tied to a specific situation, or a pattern of chronic worry across everything — that is beyond this tool (see Audience).

**Audience:** An individual managing their own uncertainty about one bounded situation. Not clinical. If the churning is part of generalized or persistent anxiety, panic, an inability to function, or any thought of self-harm, this is not a substitute for professional support — see `domain-psychology/` (e.g., the anxiety self-help set) and a licensed professional. In the US, call or text 988. This prompt handles one situation; it is not an anxiety-treatment protocol.

---

## Inputs Required

1. **The situation**, specifically — what is unresolved and why it matters (input the real stakes).
2. **The timeline** — when it might resolve, or "open-ended / unknown."
3. **The specific unknowns** the user is churning on, listed separately, in their words.
4. **What the user has been doing about the uncertainty** — over-researching, re-checking, seeking reassurance, catastrophizing, avoiding.
5. **How it's showing up** — sleep, checking behavior, inability to focus (for calibration, not diagnosis).

If input 3 is one vague blob ("everything about it"), ask the user to list the discrete open questions first — the whole method depends on sorting them individually.

---

## Instructions

### Step 1 — Sort every open question

Take each unknown from input 3 and classify it with this fixed split:

| Class | Meaning | Action |
|---|---|---|
| **Knowable now** | An action the user can take would resolve it today. | Resolve it (Step 2). |
| **Knowable later** | It resolves on a timeline, by waiting — not by effort. | Park with a check-date (Step 4). |
| **Unknowable (now)** | No one can know the outcome yet; it depends on factors outside anyone's reach. | Release; churning yields nothing (Step 4). |

Every unknown gets exactly one class. Be strict: "I could know if I asked" is knowable-now, not unknowable.

### Step 2 — Resolve the knowable-now items

For each knowable-now unknown, name the specific resolving action (send the question, run the check, get the number). These get removed from the churn by being answered, not tolerated.

### Step 3 — Define the controllable set

List what the user can do *regardless of how the situation resolves* — the actions that pay off across every branch of the outcome (prepare for two scenarios, protect the downside, keep the parts of life the situation doesn't touch running). This is where agency lives while the outcome is open.

### Step 4 — Park the rest with a mechanism

For knowable-later and unknowable items, build a concrete parking mechanism, not "try not to think about it":
- A **revisit date** (when new information will actually exist) for knowable-later items.
- An **info-diet rule** for the unknowable (e.g., no re-checking the source more than once a day) — because re-checking a genuinely open outcome produces no new information, only churn.
- A one-line reminder that worry is not a control lever: the outcome does not respond to how much the user thinks about it.

### Step 5 — Set the tolerance target (reduce, don't eliminate)

State the goal plainly: the aim is to *lower the churn to a livable level while the situation stays open*, not to manufacture certainty or force a premature decision to end the discomfort. Name one action from Steps 2–4 to do first.

---

## Constraints

### Must
- Sort every listed unknown into exactly one class.
- Resolve knowable-now items with a specific action.
- Define a controllable set that holds across outcomes.
- Park knowable-later/unknowable items with a concrete mechanism (revisit date + info-diet rule).
- Frame the target as reduced churn, not eliminated uncertainty.

### Must Not
- Classify a knowable-now item as unknowable (avoidance dressed as acceptance).
- Classify an unknowable item as knowable (feeding the over-research loop).
- Push a premature decision just to end the discomfort.
- Imply that worry or vigilance influences the outcome.
- Diagnose anxiety or prescribe a clinical treatment protocol.

---

## False-Positive Prevention

1. **Don't file a knowable-now question as unknowable.** "I can't know if they'll say yes" is often "I haven't asked yet." If an action resolves it, it's knowable-now — resolve it, don't tolerate it.
2. **Don't file an unknowable as knowable.** More research cannot resolve a genuinely open outcome; endless digging is the over-research trap, not diligence.
3. **Don't force false certainty.** Deciding prematurely to escape the discomfort is not tolerance — it's the same avoidance in a different costume.
4. **Don't treat vigilance as control.** Re-checking and worry feel productive but change nothing about an open outcome; name this explicitly.
5. **Don't scale this to generalized anxiety.** This handles one bounded situation. A pattern of chronic worry across life is a different problem — route to `domain-psychology/` (see Audience).
6. **Don't pathologize ordinary uncertainty-distress.** Discomfort waiting on a real high-stakes outcome is normal; refer only on the specific signals in the Audience note.

## Output Format

```
## Sorted unknowns
| Open question (from input 3) | Class | Action |
|---|---|---|
| ... | Knowable now / later / Unknowable | resolve / revisit-date / release |

## Resolve now
- [Knowable-now item → specific resolving action]

## Controllable across outcomes
- [Action that pays off regardless of how it resolves]
- ...

## Parked
- Knowable-later: revisit on [date, when info will exist].
- Unknowable: info-diet rule = [e.g., check at most once/day]. Worry is not a control lever.

## Tolerance target + first action
Goal: reduce churn to livable while this stays open — not force certainty. Do first: [one action].

Predicted check: within a few days, the knowable-now items are answered, the check-behavior is on its rule, and the open part occupies less of your attention.
```

## Verification

- [ ] Every listed unknown is sorted into exactly one class.
- [ ] Knowable-now items each have a specific resolving action.
- [ ] A controllable set that holds across outcomes is defined.
- [ ] Parked items have a revisit date and/or an info-diet rule.
- [ ] The target is reduced churn, not eliminated uncertainty or a forced decision.
- [ ] No knowable/unknowable misclassifications; vigilance is not framed as control.
- [ ] Clinical boundary honored; generalized anxiety routed to `domain-psychology/`.
