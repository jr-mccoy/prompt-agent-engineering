# Boundary-Setting Script Builder

## Objective

Turn a fuzzy "I need a boundary with this person" into a concrete, sayable script: the boundary named, the actual sentences to deliver it, the pushback you can expect, your prepared responses, and what you'll do if the boundary is ignored. A boundary is what *you* will do, not what you demand the other person do.

## When to Use

- A repeated dynamic (lateness, criticism, oversharing, money asks, drop-ins) you want to change.
- You keep "almost" saying something and backing down.
- You've stated a limit before and it got steamrolled.
- You want to rehearse before a specific upcoming conversation.

## Inputs / Context

- Who the boundary is with and the recurring situation.
- What's actually bothering you, in plain terms.
- What you've tried before and how it went.
- Your fear about setting it (conflict, guilt, retaliation, being seen as difficult).
- What's in your control (the consequence you can actually follow through on).
- Any safety concern (if you fear physical harm, see the safety note).

## Constraints

### Must

- Output sections in order: **The Boundary (in one line)**, **The Actual Script**, **Anticipated Pushback + My Response**, **My Follow-Through (what I do if it's ignored)**, **If I Get Flooded**.
- Phrase the boundary as a self-statement ("I will leave if…" / "I won't discuss…") not a control statement ("You have to…").
- Generate real sentences the user can say, not "you could mention…".
- The follow-through must be something the user can actually do alone, without the other person's cooperation.

### Must Not

- Don't write scripts that require the other person to agree for the boundary to "work."
- Don't escalate into ultimatums the user can't or won't enforce.
- Don't pathologize the other person or supply diagnoses.
- Don't pressure contact or confrontation if the user fears for their physical safety — route to a safety plan, a trusted person, or 988, and note that a boundary can be enacted by distance/exit rather than a conversation.

## Instructions

1. Compress the issue to a one-line boundary stated as what the user will do.
2. Write the opening sentences at the directness the relationship can bear.
3. Anticipate the 3 most likely pushback moves (guilt, anger, minimizing, negotiating) and write a one-line hold for each.
4. Define the follow-through the user controls.
5. Add a flooding backup for mid-conversation.

## Output Format

```
=== MY BOUNDARY SCRIPT ===

The Boundary (one line):
"I will [what I'll do], when [the situation]."
e.g. "I'll end the call if the conversation turns to my weight."

The Actual Script:
Opening: "I want to be straight with you about something. When [situation happens], it [effect on me]. Going forward, [the boundary, stated as my action]."
e.g. "When plans get changed last-minute, I end up scrambling and resentful. Going forward, if it's changed same-day, I'll sit that one out."

Anticipated Pushback + My Response:
- If they get hurt / guilt-trip ("So you don't care about me?"):
  "I do care. This isn't about caring less — it's about what I can keep doing."
- If they minimize ("You're overreacting"):
  "It might look small to you. It's not small to me, and this is the change I'm making."
- If they negotiate ("Just this once?"):
  "Not this time. I'm holding to it so it actually means something."
- If they get angry:
  "I'm not going to argue it. I've said what I'll do." [then disengage]

My Follow-Through (what I do if it's ignored — no permission needed):
- [The concrete action: leave, hang up, decline, stop covering the cost, not respond until X]
- I do this calmly, once, without a lecture.

If I Get Flooded:
One sentence I can fall back on: "I need to pause this — I'll come back to it." Then I step away.

Safety note (only if relevant): If I'm afraid of physical harm, I don't owe anyone a boundary conversation. I can enact the boundary by leaving / distance, and reach a trusted person or 988 if I need support.
```

## Verification

- [ ] Boundary stated as the user's own action, not a demand.
- [ ] Actual sayable sentences provided.
- [ ] At least 3 pushback types with prepared holds.
- [ ] Follow-through is enforceable by the user alone.
- [ ] Flooding backup included.
- [ ] Safety carve-out present where relevant; no pressure to confront.
