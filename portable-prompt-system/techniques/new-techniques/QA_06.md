# QA-06: Constitutional AI for Prompts

## Category
Quality Assurance (QA)

## Description
Constitutional AI for Prompts applies self-correction principles with critique-revise loops to improve prompt quality through iterative refinement against defined constitutional principles. Instead of accepting the first prompt version, this technique systematically evaluates prompts against quality principles (clarity, completeness, consistency, conciseness, correctness), identifies violations, generates improved versions, and repeats the cycle multiple times to harden prompts before production deployment.

## When to Use

Use Constitutional AI for Prompts when:

1. **Production-Critical Prompts**: Deploying prompts to live systems where quality directly impacts users
2. **Complex Prompts**: Multi-step prompts with intricate logic requiring systematic review
3. **Hardening Before Deployment**: Need to catch edge cases and ambiguities before production
4. **Quality Assurance Process**: Establishing systematic prompt review workflow
5. **Training Prompt Engineers**: Teaching best practices through structured critique
6. **Avoiding Common Pitfalls**: Need to systematically check for known prompt engineering issues

## Phase 1: Generate Initial Prompt (v1.0)

```markdown

When a customer asks for help:

2. Find a solution
3. Respond helpfully

Be nice and solve their problems.
```

**Initial Version Score:** ?/25 (to be evaluated)

---

## Phase 2: Critique v1.0 Against Constitutional Principles

### Principle 1: Clarity (Is every instruction unambiguous?)

**Rating:** 1/5 (Very Unclear)

**Violations Found:**
1. "Help customers with their issues" - HOW? What actions are allowed?
2. "Understand their problem" - How deeply? What information to extract?
3. "Find a solution" - From where? What resources available?
4. "Respond helpfully" - What does "helpful" mean specifically?
5. "Be nice" - Too vague, no concrete tone guidelines

**Impact:**
- Agent might give inconsistent responses
- Agent might promise things company can't deliver
- Agent might not collect required information
- Tone could vary wildly (too casual, too formal, inconsistent)

**Examples of Ambiguity:**
- Does "solve their problems" mean offering refunds? Free replacements?
- What if customer is angry? How "nice" should the agent be?

---

### Principle 2: Completeness (Are all edge cases handled?)

**Rating:** 1/5 (Severely Incomplete)

**Violations Found:**
1. No guidance for when agent CAN'T solve problem (escalation)
2. No handling of rude/abusive customers
3. No handling of requests outside scope (non-product questions)
4. No guidance on information collection (order number, customer ID)
5. No policy constraints (refund limits, return windows)
6. No error handling (missing information, unclear requests)

**Impact:**
- Agent will fail on complex cases requiring escalation
- Agent might handle abuse poorly
- Agent might answer off-topic questions (waste time)
- Agent might offer refunds outside policy (cost company money)

**Missing Edge Cases:**
- Customer asks for full refund outside return window
- Customer is verbally abusive
- Customer's issue isn't in knowledge base
- Customer provides incomplete information

---

### Principle 3: Consistency (Do instructions contradict?)

**Rating:** 3/5 (Some Inconsistencies)

**Violations Found:**
1. "Help customers" vs. unstated company policies (which wins?)
2. "Be nice" vs. escalating abusive customers (contradictory)

**Impact:**
- Agent might prioritize customer satisfaction over company policy
- Agent might tolerate abuse instead of escalating

---

### Principle 4: Conciseness (Any unnecessary verbosity?)

**Rating:** 4/5 (Reasonably Concise)

**Violations Found:**
- Minimal redundancy
- Could be more specific without adding much length

**Impact:**
- Minor issue (prompt is short but TOO short - lacks detail)

---

### Principle 5: Correctness (Will this achieve the goal?)

**Rating:** 1/5 (Won't Reliably Work)

**Violations Found:**
1. No knowledge base access defined - agent can't "find solutions"
2. No policy enforcement - agent will make up refund rules
3. No structured workflow - agent will improvise (inconsistent)
4. No success criteria - agent doesn't know what "solved" means

**Impact:**
- Agent will hallucinate policies ("I can offer you a 50% refund!")
- Agent will give inconsistent responses to same question
- Agent won't achieve 80% resolution target (no structure)

### Revised Prompt (v1.1)

```markdown
# Customer Support AI Agent

## Role
You are a customer support agent for AcmeCommerce. Your goal is to resolve customer
issues efficiently while following company policies.

## Resources Available
- **Knowledge Base:** Product information, troubleshooting guides, FAQ
- **Customer Account:** Order history, shipping status, account details
- **Company Policies:** Refund policy (30-day window), return shipping (customer pays),
  price match (competitor prices)

## Workflow

### Step 1: Gather Information
Extract the following from customer message:
- Customer name and order number (required)
- Issue type: Order issue, Product issue, Account issue, General inquiry
- Issue details and severity

If information missing, ask politely:
"To help you effectively, I'll need your order number. You can find it in your
confirmation email."

### Step 2: Classify Issue
Determine issue category:
- **Refund/Return:** Customer wants money back or to return product
- **Shipping:** Package lost, delayed, or damaged
- **Product Defect:** Product not working as expected
- **Account:** Login issues, password reset, account settings
- **General:** Questions about products, policies, or company

### Step 3: Resolve Issue
**For Refund/Return:**
- Check order date (within 30-day return window?)
- If YES: "I can process a return for you. You'll receive a return shipping label
  via email. Once we receive the item, we'll refund your payment within 5-7 business days."
- If NO: "I understand your frustration. Our return policy is 30 days from purchase.
  Your order was placed [X] days ago, which is outside the window. However, I can
  escalate this to my supervisor for a possible exception."

**For Shipping:**
- Check tracking status in system
- If package lost (>10 days late): "I apologize for the delay. I'm issuing a
  replacement shipment at no charge. You'll receive tracking info within 24 hours."
- If package delayed (<10 days): "Your package is currently delayed but in transit.
  Expected delivery: [date]. I'll monitor this and follow up if it doesn't arrive."

**For Product Defect:**
- Offer troubleshooting from knowledge base first
- If unresolved: Offer replacement or refund (within 30-day window)

**For Account:**
- Password reset: "I've sent a password reset link to [email]. Check spam folder."
- Other account issues: Escalate to technical support team

**For General:**
- Answer from knowledge base
- If outside scope (e.g., "What's the weather?"): "I'm specialized in helping with
  AcmeCommerce orders and products. For other questions, I recommend [resource]."

### Step 4: Confirm Resolution
Ask: "Does this solve your issue?" or "Is there anything else I can help you with today?"

If customer satisfied: Mark ticket as Resolved
If customer unsatisfied: Escalate to human agent

## Edge Case Handling

**Abusive Customer:**
"I understand you're frustrated, but I need you to communicate respectfully so I can
help you effectively. If this continues, I'll need to end this conversation and have
a supervisor reach out."

**Request Outside Policy:**
"I'd like to help, but that's outside our standard policy. Let me escalate this to
my supervisor who can review your case individually."

**Unclear Request:**
"I want to make sure I understand correctly. Are you asking about [interpretation]?"

**Missing Information:**
"To move forward, I'll need [specific information]. Can you provide that?"

## Tone Guidelines
- Empathetic: Acknowledge customer frustration
- Professional: Avoid slang, use proper grammar
- Solution-oriented: Focus on what CAN be done
- Concise: Avoid unnecessary elaboration

## Constraints (NEVER Violate)
- Never promise refunds outside 30-day window without supervisor approval
- Never ask for credit card information (we have it on file)
- Never share customer data with others
- Never make up policies (if uncertain, escalate)

## Success Criteria
Issue is resolved when:
1. Customer's request addressed per policy
2. Customer confirms satisfaction
3. OR issue escalated to human agent with context
```

**Revised Version:** v1.1 complete

## Pitfalls

### Pitfall 1: Skipping Iterations

**Problem:** Accepting first revision without further critique

**Example (BAD):**
```markdown
v1.0 (score 10/25) → v1.1 (score 18/25)
**Decision:** "Good enough, deploying!"

**Result:** Fails in production (18/25 < 23/25 threshold)
```

**Solution:** Iterate until quality threshold met

**Example (GOOD):**
```markdown
v1.0 (10/25) → v1.1 (18/25) → v1.2 (22/25) → v1.3 (24/25)
**Decision:** Deploy v1.3 (meets 23/25 threshold)
```

### Pitfall 2: Vague Principles

**Problem:** Principles too abstract to evaluate

**Example (BAD):**
```markdown
Principle: "Prompt should be good"

**Evaluation:** "Is it good?" ... "I think so?"
```

**Solution:** Specific, measurable principles

**Example (GOOD):**
```markdown
Principle: Clarity - Every instruction has a single interpretation

**Evaluation:**
- Instruction: "Help the customer" ← VAGUE (many interpretations)
- Instruction: "Process refund within 24 hours" ← CLEAR (one interpretation)
```

### Pitfall 3: Not Addressing All Violations

**Problem:** Fixing some issues but ignoring others

**Example (BAD):**
```markdown
**Critique Found:**
1. Missing edge case handling (Completeness)
2. Contradictory instructions (Consistency)
3. Vague terminology (Clarity)

**Revision:**
- Fixed #1 (edge cases)
- Ignored #2 and #3

**Result:** Still fails Consistency and Clarity checks
```

**Solution:** Address ALL identified violations

### Pitfall 4: Introducing New Issues While Fixing Others

**Problem:** Revision creates new problems

**Example (BAD):**
```markdown
**v1.0 Issue:** Missing refund policy
**v1.1 Fix:** Added refund policy (Completeness improved)
**v1.1 New Issue:** Refund policy contradicts return policy (Consistency degraded)

**Net:** +2 Completeness, -2 Consistency = no improvement
```

**Solution:** Re-evaluate after each revision

### Pitfall 5: Over-Optimizing for One Principle

**Problem:** Sacrificing other principles to perfect one

**Example (BAD):**
```markdown
**Objective:** Perfect Clarity

**v1.2:** Added 50 examples to clarify every edge case
**Result:**
- Clarity: 5/5 ✅
- Conciseness: 1/5 ❌ (now 10,000 words, unreadable)
- Correctness: 2/5 ❌ (so long that core logic is buried)

**Worse than v1.0**
```

**Solution:** Balance all principles

## Summary

Constitutional AI for Prompts (QA-06) systematically improves prompt quality through iterative critique-revise loops against defined principles (Clarity, Completeness, Consistency, Conciseness, Correctness). By evaluating prompts against each principle, identifying specific violations, and revising to address issues, this technique hardens prompts before production deployment and prevents failures that single-pass reviews miss.

**Key Takeaway:** Never deploy the first version of a critical prompt. Apply constitutional AI critique-revise loops (minimum 2-3 iterations) to systematically identify and fix quality issues before production.
