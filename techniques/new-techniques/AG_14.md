# AG-14: Cost-Aware Agent Orchestration

## Category
Agentic (AG)

## Description
Cost-Aware Agent Orchestration strategically assigns LLM models (Opus/Sonnet/Haiku) based on task criticality, treating cost as an explicit optimization parameter alongside quality and speed. Instead of using one model for all tasks or randomly selecting models, this technique evaluates the criticality and complexity of each workflow step and assigns the most cost-effective model that meets quality requirements, optimizing the cost-to-value ratio across the entire workflow.

## When to Use

Use Cost-Aware Agent Orchestration when:

1. **Multi-Agent Systems**: Workflows involving multiple agents performing tasks of varying criticality
2. **Production AI Systems**: Budget constraints require cost optimization without sacrificing quality
3. **High-Volume Workflows**: Many tasks executed daily where small per-task savings compound significantly
4. **Varying Task Complexity**: Mix of simple (formatting) and complex (architecture decisions) tasks
5. **Quality-Cost Tradeoffs**: Need to balance quality requirements with budget limits
6. **Model Tier Availability**: Access to multiple model tiers (Claude Opus, Sonnet, Haiku or GPT-4, GPT-3.5, etc.)

## Pattern

### Structural Template

```markdown
## Cost-Aware Model Assignment Strategy

### Model Tier Definitions

**Tier 1: Premium Model** (e.g., Claude Opus 4.5)
- **Cost:** ~$15 per 1M input tokens, ~$75 per 1M output tokens
- **Strengths:** Complex reasoning, critical decisions, high-stakes tasks
- **Weaknesses:** Expensive, slower
- **Use when:** Mistakes are costly to fix

**Tier 2: Balanced Model** (e.g., Claude Sonnet 4.5)
- **Cost:** ~$3 per 1M input tokens, ~$15 per 1M output tokens
- **Strengths:** Good reasoning, reasonable cost, fast
- **Weaknesses:** Less capable than Premium for very complex tasks
- **Use when:** Complexity requires reasoning but not critical

**Tier 3: Economy Model** (e.g., Claude Haiku 4.5)
- **Cost:** ~$0.25 per 1M input tokens, ~$1.25 per 1M output tokens
- **Strengths:** Very fast, very cheap, good for simple tasks
- **Weaknesses:** Limited reasoning ability
- **Use when:** Speed and cost matter more than depth

## Task Classification Framework

For each workflow step, evaluate:

### Criticality Assessment
**High:** Mistakes expensive to fix (architecture decisions, security reviews)
**Medium:** Mistakes fixable but time-consuming (implementation, testing)
**Low:** Mistakes trivial to fix (formatting, documentation)

### Complexity Assessment
**High:** Requires deep reasoning (system design, algorithm selection)
**Medium:** Requires moderate reasoning (feature implementation)
**Low:** Deterministic or pattern-matching (syntax checking, formatting)

### Assignment Matrix

| Criticality | Complexity | Model Tier | Example Tasks |

---

## Cost Optimization Rules

### Rule 1: Never Over-Provision
Don't use Opus for tasks Haiku can handle adequately

### Rule 2: Never Under-Provision
Don't use Haiku for critical decisions where mistakes are expensive

### Rule 3: Monitor and Adjust
Track cost per task, flag anomalies (>20% increase), adjust model assignments

### Rule 4: Batch Similar Tasks
Group low-priority tasks for Haiku to maximize efficiency

### Rule 5: Default to Balanced
Use Sonnet as default, upgrade to Opus or downgrade to Haiku based on results
```

```python
# JWT Implementation (Sonnet 4.5)

import jwt
from datetime import datetime, timedelta
from config import JWT_SECRET, JWT_ALGORITHM

def generate_access_token(user_id: str) -> str:
    """Generate short-lived access token (15 minutes)"""
    payload = {
        'user_id': user_id,
        'type': 'access',
        'exp': datetime.utcnow() + timedelta(minutes=15),
        'iat': datetime.utcnow()
    }
    return jwt.encode(payload, JWT_SECRET, algorithm=JWT_ALGORITHM)

def generate_refresh_token(user_id: str) -> str:
    """Generate long-lived refresh token (7 days)"""
    payload = {
        'user_id': user_id,
        'type': 'refresh',
        'exp': datetime.utcnow() + timedelta(days=7),
        'iat': datetime.utcnow()
    }
    token = jwt.encode(payload, JWT_SECRET, algorithm=JWT_ALGORITHM)

    # Store token hash in database for rotation tracking
    token_hash = hashlib.sha256(token.encode()).hexdigest()
    db.insert_refresh_token(user_id, token_hash)

    return token

def validate_token(token: str, token_type: str) -> dict:
    """Validate JWT token and check blacklist"""
    try:
        payload = jwt.decode(token, JWT_SECRET, algorithms=[JWT_ALGORITHM])

        if payload['type'] != token_type:
            raise InvalidTokenError(f"Expected {token_type} token")

        # Check blacklist
        token_hash = hashlib.sha256(token.encode()).hexdigest()
        if db.is_token_blacklisted(token_hash):
            raise TokenBlacklistedError()

        return payload
    except jwt.ExpiredSignatureError:
        raise TokenExpiredError()
    except jwt.InvalidTokenError:
        raise InvalidTokenError()
```

### Variation 2: Budget-Constrained Optimization

Allocate budget across tasks:

```python
def optimize_within_budget(tasks, total_budget_dollars):
    """Assign models to maximize quality within budget"""

    # Sort tasks by criticality (high-criticality gets budget priority)
    sorted_tasks = sorted(tasks, key=lambda t: t.criticality, reverse=True)

    remaining_budget = total_budget_dollars
    assignments = []

    for task in sorted_tasks:
        # Try to assign best model within remaining budget
        for model in ['opus', 'sonnet', 'haiku']:
            estimated_cost = estimate_task_cost(task, model)

            if estimated_cost <= remaining_budget:
                assignments.append({'task': task, 'model': model})
                remaining_budget -= estimated_cost
                break
        else:
            # No model fits budget
            raise BudgetExhaustedError(f"Cannot afford {task} within budget")

    return assignments
```

```python
    for item in prioritized:
        item_tokens = estimate_tokens(item)
        item_cost = item_tokens * cost_per_input_token

        if consumed_tokens + item_tokens <= token_budget and \
           consumed_cost + item_cost <= cost_budget:
            loaded.append(item)
            consumed_tokens += item_tokens
            consumed_cost += item_cost
        else:
            break

    return loaded, consumed_tokens, consumed_cost
```

## Pitfalls

### Pitfall 1: Penny-Wise, Pound-Foolish

**Problem:** Using cheap model for critical task, causing expensive rework

**Example (BAD):**
```markdown
## Architecture Design (Haiku - save money!)
**Cost:** $0.05

**Result:** Fundamentally flawed architecture chosen
**Rework Cost:** 4 weeks of development thrown away = $40,000

**Total:** $0.05 saved, $40,000 lost
```

**Solution:** Never skimp on critical decisions

**Example (GOOD):**
```markdown
## Architecture Design (Opus)
**Cost:** $0.50

**Result:** Solid architecture, no rework needed
**Saved:** $40,000 in potential rework

**ROI:** 80,000:1
```

### Pitfall 2: Not Measuring Quality

**Problem:** Assuming cheaper model quality is acceptable without validation

**Example (BAD):**
```python
# Switch all tasks to Haiku to save money
for task in tasks:
    result = haiku.execute(task)  # No quality validation!
    deploy(result)

# Result: Bugs in production, poor quality
```

**Solution:** Measure quality across model tiers

**Example (GOOD):**
```python
# A/B test: Sonnet vs. Haiku for this task type
sonnet_results = [sonnet.execute(task) for task in sample_tasks]
haiku_results = [haiku.execute(task) for task in sample_tasks]

sonnet_quality = measure_quality(sonnet_results)  # 95%
haiku_quality = measure_quality(haiku_results)     # 75%

if haiku_quality >= quality_threshold:
    use_model = 'haiku'  # Adequate quality, lower cost
else:
    use_model = 'sonnet'  # Quality matters more than cost
```

### Pitfall 3: Ignoring Compounding Costs

**Problem:** Small per-task cost differences compound over high-volume workflows

**Example (BAD):**
```markdown
Task: Generate daily report (365 days/year)

**Opus:** $0.50 per report
**Annual cost:** $0.50 × 365 = $182.50

**Haiku:** $0.02 per report
**Annual cost:** $0.02 × 365 = $7.30

**Ignored savings:** $175.20/year by not switching to Haiku
```

**Solution:** Calculate annualized costs for recurring tasks

### Pitfall 4: Model Assignment Inconsistency

**Problem:** No systematic approach; arbitrary model selection

**Example (BAD):**
```markdown
Monday: Use Opus (I feel like quality today)
Tuesday: Use Haiku (need to save money)
Wednesday: Use Sonnet (compromise)

**Result:** Inconsistent quality, unpredictable costs
```

**Solution:** Systematic classification and assignment rules

**Example (GOOD):**
```python
def assign_model(task):
    """Consistent model assignment based on objective criteria"""
    criticality = assess_criticality(task)
    complexity = assess_complexity(task)

    return MODEL_ASSIGNMENT_MATRIX[(criticality, complexity)]
```

### Pitfall 5: Optimizing Before Baseline

**Problem:** Optimizing costs without knowing current spend

**Example (BAD):**
```markdown
"Let's use Haiku for everything to save money!"

**Question:** How much are we spending now?
**Answer:** We don't know...

**Result:** Optimizing blindly, may hurt quality unnecessarily
```

**Solution:** Measure current costs before optimizing

**Example (GOOD):**
```markdown
## Week 1: Baseline (all Sonnet)
**Total cost:** $50
**Quality:** 95% approval rate

## Week 2: Optimize (strategic model assignment)
**Total cost:** $20
**Quality:** 94% approval rate

**Result:** 60% cost reduction, 1% quality drop (acceptable tradeoff)
```
