# CM-07: Token-Budget-Aware Progressive Loading

## Category
Context Management (CM)

## Description
Token-Budget-Aware Progressive Loading dynamically loads context components in priority order until the token budget is exhausted, maximizing utility within API constraints. Rather than loading all available context (which may exceed limits) or arbitrarily truncating context, this technique prioritizes components by importance and progressively loads them until the budget is consumed, ensuring the most valuable information is always included.

## When to Use

Use Token-Budget-Aware Progressive Loading when:

1. **Large Context Repositories**: Available context exceeds API token limits
2. **Long-Running Projects**: Resuming work with extensive accumulated history
3. **RAG Systems**: Retrieval produces more relevant documents than fit in context window
4. **Production AI Systems**: Strict token budgets for cost control
5. **Multi-Session Workflows**: Context grows over time and must be selectively loaded
6. **Cost-Sensitive Applications**: Need to maximize value per token

### 3. Progressive Loading Algorithm
```python
def load_context_within_budget(components, token_budget):
    prioritized = sort_by_priority(components)  # Tier 1, then Tier 2, then Tier 3
    loaded_context = []
    consumed_tokens = 0

    for component in prioritized:
        component_tokens = estimate_tokens(component)

        if consumed_tokens + component_tokens <= token_budget:
            loaded_context.append(component)
            consumed_tokens += component_tokens
        else:
            # Budget exhausted
            log_excluded(component, reason="Budget limit reached")
            break

    return loaded_context, consumed_tokens
```

- ⚠️ Excluded: {LIST_OF_EXCLUDED_COMPONENTS} ({EXCLUDED_TOKENS} tokens)
- Budget utilization: {PERCENTAGE}%
```

## Step 2: Progressive Loading with Budget

```python
# Implementation of progressive loading

def estimate_tokens(text):
    """Rough token estimation: ~1.3 tokens per word"""
    words = len(text.split())
    return int(words * 1.3)

def load_context_within_budget(components, budget=20000):
    """
    Load context components progressively until budget exhausted

    Args:
        components: List of {content, priority, name} dicts
        budget: Maximum tokens to consume

    Returns:
        loaded_contexts: List of loaded components
        total_tokens: Tokens consumed
        excluded: List of excluded components
    """
    # Sort by priority (descending)
    sorted_components = sorted(components, key=lambda x: x['priority'], reverse=True)

    loaded = []
    excluded = []
    consumed_tokens = 0

    for component in sorted_components:
        component_tokens = estimate_tokens(component['content'])

        if consumed_tokens + component_tokens <= budget:
            # Fits in budget - load it
            loaded.append({
                'name': component['name'],
                'content': component['content'],
                'tokens': component_tokens,
                'priority': component['priority']
            })
            consumed_tokens += component_tokens
            print(f"✅ Loaded: {component['name']} ({component_tokens} tokens, priority {component['priority']})")
        else:
            # Exceeds budget - exclude it
            excluded.append({
                'name': component['name'],
                'tokens': component_tokens,
                'priority': component['priority'],
                'reason': 'Budget limit reached'
            })
            print(f"⚠️ Excluded: {component['name']} ({component_tokens} tokens, priority {component['priority']})")

    print(f"\n📊 Budget Utilization: {consumed_tokens}/{budget} tokens ({consumed_tokens/budget*100:.1f}%)")
    print(f"📦 Loaded: {len(loaded)} components")
    print(f"🚫 Excluded: {len(excluded)} components")

    return loaded, consumed_tokens, excluded


# Example usage

### Variation 2: Token Estimation with Actual Tokenizer

Use real tokenizer for accurate counting:

```python
import tiktoken

def estimate_tokens_accurate(text, model="gpt-4"):
    encoding = tiktoken.encoding_for_model(model)
    return len(encoding.encode(text))

# More accurate budget management
component_tokens = estimate_tokens_accurate(component['content'])
```

### Variation 3: Dynamic Budget Adjustment

Adjust budget based on conversation length:

```python
conversation_tokens = estimate_tokens(conversation_history)
remaining_budget = API_LIMIT - conversation_tokens - RESERVE_BUFFER

# As conversation grows, context budget shrinks
loaded_contexts = load_within_budget(components, budget=remaining_budget)
```

### Variation 4: Summarization for Oversized Components

If a high-priority component exceeds budget, summarize it:

```python
if component_tokens > budget_remaining and component['priority'] >= 80:
    # Summarize to fit
    summary = summarize(component['content'], target_tokens=budget_remaining)
    loaded.append(summary)
else:
    # Skip entirely
    excluded.append(component)
```

## Pitfalls

### Pitfall 1: Poor Prioritization
**Problem:** All components marked as high priority

**Example (BAD):**
```python
components = [
    {'name': 'Current task', 'priority': 100},
    {'name': 'Active blocker', 'priority': 100},
    {'name': 'Random old doc', 'priority': 100},  # Everything is critical!
    {'name': 'Unrelated code', 'priority': 100},
    # ...everything priority 100
]
```

**Result:** Loads in arbitrary order until budget exhausted (no real prioritization)

**Solution:** Use differentiated priority scores

**Example (GOOD):**
```python
components = [
    {'name': 'Current task', 'priority': 100},
    {'name': 'Active blocker', 'priority': 95},
    {'name': 'Recent decision', 'priority': 85},
    {'name': 'Historical context', 'priority': 40},
]
```

### Pitfall 2: Inaccurate Token Estimation
**Problem:** Estimates way off, exceeding budget

**Example (BAD):**
```python
def estimate_tokens(text):
    return len(text) / 4  # Wildly inaccurate
```

**Solution:** Use proper tokenizer or conservative estimates

**Example (GOOD):**
```python
import tiktoken
def estimate_tokens(text):
    encoding = tiktoken.encoding_for_model("gpt-4")
    return len(encoding.encode(text))
```

### Pitfall 3: Not Logging Exclusions
**Problem:** Context silently excluded, user doesn't know

**Example (BAD):**
```python
if consumed + component_tokens > budget:
    continue  # Silently skip
```

**Solution:** Log all exclusions with reasons

**Example (GOOD):**
```python
if consumed + component_tokens > budget:
    log_excluded(component['name'], reason="Budget limit", tokens=component_tokens)
    excluded.append(component)
```

### Pitfall 4: Static Budgets
**Problem:** Budget doesn't adapt to conversation length

**Example (BAD):**
```python
budget = 20000  # Always 20K, even when conversation consumes 80K
```

**Solution:** Dynamic budget based on remaining capacity

**Example (GOOD):**
```python
API_LIMIT = 100000
conversation_tokens = estimate_tokens(conversation_history)
budget = API_LIMIT - conversation_tokens - 10000  # Reserve 10K for response
```

### Pitfall 5: All-or-Nothing Loading
**Problem:** Large components either fully loaded or fully excluded

**Example (BAD):**
```python
# 15K token component won't fit in 12K remaining budget - skip entirely
if component_tokens > budget_remaining:
    excluded.append(component)
```

**Solution:** Summarize large high-priority components

**Example (GOOD):**
```python
if component_tokens > budget_remaining and component['priority'] >= 80:
    # Summarize to fit
    summary = summarize(component, target_tokens=budget_remaining)
    loaded.append(summary)
```

## Summary

Token-Budget-Aware Progressive Loading (CM-07) ensures AI systems stay within API token limits while maximizing the value of loaded context. By prioritizing components and progressively loading until the budget is exhausted, this technique guarantees that the most important information is always included and less important context is excluded gracefully.

**Key Takeaway:** If your AI system has more available context than fits in the API limit, implement token-budget-aware progressive loading with explicit prioritization to maximize value within constraints.
