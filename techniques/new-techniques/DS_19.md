# DS-19: Multi-Source Narrative Synthesis

## Category
Domain-Specific (DS)

## Description
Multi-Source Narrative Synthesis combines structured data from multiple fragmented tools (Git, Jira, Calendar, Obsidian, Slack) into coherent narratives for status reporting. Instead of manually aggregating information across systems, this technique systematically correlates data from different sources, resolves conflicts, and generates unified narratives that communicate progress clearly to both technical and non-technical stakeholders.

## When to Use

Use Multi-Source Narrative Synthesis when:

1. **Fragmented Tool Landscape**: Team uses multiple disconnected tools (Git, Jira, Calendar, documentation)
2. **Status Reporting**: Regular standups, weekly updates, or sprint reviews requiring information synthesis
3. **Async Team Communication**: Distributed teams across timezones needing comprehensive written updates
4. **Stakeholder Reporting**: Need to communicate progress to both technical and non-technical audiences
5. **Preventing Information Loss**: Important context scattered across multiple systems
6. **Time-Consuming Manual Synthesis**: Currently spending significant time aggregating information by hand

## Phase 2: Data Correlation

### Correlation Strategy

**1. Git Commits ↔ Jira Tickets**

Extract ticket references from commit messages:

```python
import re

def correlate_commits_to_tickets(commits, tickets):
    correlations = []

    for commit in commits:
        # Extract ticket reference from commit message
        match = re.search(r'(PROJ-\d+)', commit['message'])

        if match:
            ticket_key = match.group(1)
            # Find corresponding Jira ticket
            ticket = next((t for t in tickets if t['key'] == ticket_key), None)

            if ticket:
                correlations.append({
                    'commit': commit,
                    'ticket': ticket,
                    'status': 'correlated'
                })
            else:
                correlations.append({
                    'commit': commit,
                    'ticket': None,
                    'status': 'orphaned_commit'  # Commit references non-existent ticket
                })

    return correlations
```

```python
def correlate_commits_to_notes(commits, notes):
    correlations = []

    for commit in commits:
        commit_date = datetime.fromisoformat(commit['timestamp'])

        for note in notes:
            note_date = datetime.fromisoformat(note['created'])

            # Same day and overlapping keywords
            if commit_date.date() == note_date.date():
                commit_keywords = set(commit['message'].lower().split())
                note_keywords = set(note['content'].lower().split())

                if len(commit_keywords & note_keywords) >= 3:  # 3+ shared words
                    correlations.append({
                        'commit': commit,
                        'note': note,
                        'relevance': 'high'
                    })

    return correlations
```

## Phase 3: Conflict Resolution

### Common Conflicts and Resolution Strategies

**Conflict 1: Git Says "Done", Jira Says "In Progress"**

```python
def resolve_status_conflict(commit, ticket):
    """
    Git commits suggest work is complete, but Jira ticket still "In Progress"

    Resolution: Trust Git (code is source of truth), but flag for review
    """
    if commit['message'].startswith('feat:') and ticket['status'] == 'In Progress':
        return {
            'resolved_status': 'Done (pending Jira update)',
            'action': f"Update {ticket['key']} to Done",
            'confidence': 'high'
        }

    return {'resolved_status': ticket['status'], 'confidence': 'low'}
```

**Conflict 2: Multiple Commits for Same Ticket with Different Types**

```python
def resolve_commit_type_conflict(commits_for_ticket):
    """
    PROJ-123 has commits: "feat:", "fix:", "refactor:"

    Resolution: Categorize as most significant type (feat > fix > refactor)
    """
    priority = {'feat': 3, 'fix': 2, 'refactor': 1, 'chore': 0}

    commit_types = [extract_type(c['message']) for c in commits_for_ticket]
    primary_type = max(commit_types, key=lambda t: priority.get(t, 0))

    return {
        'primary_type': primary_type,
        'all_types': commit_types,
        'summary': f"{primary_type} with additional {', '.join(set(commit_types) - {primary_type})}"
    }
```

**Conflict 3: Calendar Shows No Time, but Commits Exist**

```python
def resolve_time_conflict(commits, calendar_events):
    """
    Commits exist but calendar shows 8 hours of meetings

    Resolution: Commits happened outside work hours or on weekends
    """
    commit_timestamps = [datetime.fromisoformat(c['timestamp']) for c in commits]
    work_hours = range(9, 18)  # 9am-6pm

    after_hours_commits = [
        c for c in commit_timestamps
        if c.hour not in work_hours or c.weekday() >= 5  # Weekend
    ]

    if after_hours_commits:
        return {
            'context': f"Work done outside standard hours ({len(after_hours_commits)} commits)",
            'flag': 'potential_overtime'
        }

    return {'context': 'Standard work hours'}
```

### Synthesis Algorithm

```python
def synthesize_standup_narrative(correlated_data, conflicts_resolved):
    """
    Transform structured data into human-readable standup update
    """

    narrative = {
        'yesterday': [],
        'today': [],
        'blockers': []
    }

    # Yesterday: Completed work
    for item in correlated_data:
        if item['ticket']['status'] == 'Done':
            narrative['yesterday'].append({
                'type': extract_commit_type(item['commit']['message']),
                'ticket': item['ticket']['key'],
                'description': item['ticket']['summary'],
                'technical_details': item['commit']['message'],
                'context': find_related_note(item, notes)
            })

    # Today: In Progress work
    for item in correlated_data:
        if item['ticket']['status'] == 'In Progress':
            narrative['today'].append({
                'ticket': item['ticket']['key'],
                'description': item['ticket']['summary'],
                'progress': estimate_progress(item['commit'], item['ticket']),
                'estimated_completion': 'end of day'
            })

    # Blockers: Extract from Slack + Jira comments
    for ticket in tickets:
        for comment in ticket['comments']:
            if any(keyword in comment['body'].lower() for keyword in ['blocked', 'waiting', 'need help']):
                narrative['blockers'].append({
                    'ticket': ticket['key'],
                    'description': ticket['summary'],
                    'blocker': comment['body'],
                    'needs': extract_needs(comment['body'])
                })

    return narrative
```

## Pitfalls

### Pitfall 1: Data Source Staleness

**Problem:** Sources update at different rates; synthesis uses stale data

**Example (BAD):**
```python
# Jira cache updated hourly, Git in real-time
jira_data = get_cached_jira()  # 55 minutes old
git_data = get_live_git()  # Real-time

synthesize(jira_data, git_data)
# Result: Git shows commit for PROJ-123, Jira still shows "In Progress"
# Synthesis incorrectly flags conflict
```

**Solution:** Timestamp all data sources and warn about staleness

**Example (GOOD):**
```python
jira_data = get_jira()
jira_timestamp = jira_data['fetched_at']

if (datetime.now() - jira_timestamp).seconds > 600:  # 10 minutes
    warn(f"Jira data is {minutes_old} minutes old - synthesis may be stale")

synthesize(jira_data, git_data, timestamps={'jira': jira_timestamp, 'git': git_timestamp})
```

### Pitfall 2: Over-Correlation

**Problem:** Falsely correlating unrelated data from different sources

**Example (BAD):**
```python
# Correlate calendar event to Jira ticket by any keyword match
event = "Team Lunch"
ticket = "PROJ-123: Implement lunch menu feature"

if 'lunch' in event.lower() and 'lunch' in ticket['summary'].lower():
    correlate(event, ticket)  # WRONG - team lunch != feature work
```

**Solution:** Use multiple signals for correlation

**Example (GOOD):**
```python
def correlate_event_to_ticket(event, ticket):
    # Require multiple correlation signals
    signals = {
        'ticket_key_in_summary': ticket['key'] in event['summary'],
        'keyword_overlap': len(set(event_keywords) & set(ticket_keywords)) >= 3,
        'attendees_include_assignee': ticket['assignee'] in event['attendees'],
        'time_proximity': within_same_workday(event, ticket['updated'])
    }

    # Require at least 2 signals
    if sum(signals.values()) >= 2:
        return True
    return False
```

### Pitfall 3: Missing Conflict Resolution

**Problem:** Conflicts not resolved; synthesis includes contradictory information

**Example (BAD):**
```markdown
## Yesterday

**PROJ-123:** Completed (per Git commits: "feat: Complete OAuth implementation")

**PROJ-123:** In Progress (per Jira status)

**User is confused:** Is it done or not?
```

**Solution:** Explicit conflict resolution with explanation

**Example (GOOD):**
```markdown
## Yesterday

**PROJ-123: Implement OAuth2 authentication**

**Status:** ✅ Complete (pending Jira update)
- Git: 15 commits including "feat: Complete OAuth implementation"
- Jira: Still shows "In Progress" (needs manual status update)
- **Resolution:** Code is complete and merged; Jira status will be updated shortly

**Action:** Update PROJ-123 status to "Done" in Jira
```

### Pitfall 4: Information Overload

**Problem:** Synthesis includes everything from all sources without prioritization

**Example (BAD):**
```markdown
## Yesterday (from all sources)

**Git:**
- Commit a1b2c3d: "feat: Add function"
- Commit e4f5g6h: "fix: typo"
- Commit i8j9k0l: "chore: update deps"
... (50 more commits)

**Jira:**
- PROJ-123: Comment added "looks good"
- PROJ-124: Comment added "approved"
... (30 more ticket updates)

**Calendar:**
- 9am-9:15am: Standup
- 9:15am-9:30am: Coffee break
... (20 more events)

**Total:** 5,000 words of synthesized data (nobody reads it)
```

**Solution:** Prioritize and summarize

**Example (GOOD):**
```markdown
## Yesterday

### Key Accomplishments (2 items)
- ✅ PROJ-123: OAuth implementation complete (15 commits)
- ✅ PROJ-456: Memory leak fixed (3 commits)

### Time Allocation
- Coding: 5.5 hours (69%)
- Meetings: 2.5 hours (31%)

### Details (if needed)
<details>
<summary>Full commit list (18 commits)</summary>

- a1b2c3d: feat: Add token refresh
- e4f5g6h: fix: Handle edge case
(... full list)

</details>
```

### Pitfall 5: No Validation of Synthesis Quality

**Problem:** Automated synthesis produces narrative without human validation

**Example (BAD):**
```python
# Generate standup automatically and send to team
narrative = synthesize_standup(git, jira, calendar)
send_to_slack(narrative)  # No review!

# Result: Synthesis includes private Slack thread, sensitive information leaked
```

**Solution:** Human-in-the-loop validation

**Example (GOOD):**
```python
# Generate synthesis
narrative = synthesize_standup(git, jira, calendar)

# Flag for review
flags = validate_synthesis(narrative)
# Flags: [contains_private_info, missing_blocker_context, stale_jira_data]

if flags:
    print(f"⚠️ Review required: {flags}")
    narrative_reviewed = prompt_for_review(narrative)
    send_to_slack(narrative_reviewed)
else:
    print("✅ Synthesis validated, sending...")
    send_to_slack(narrative)
```
