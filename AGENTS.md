# AGENTS.md — Prompt & Agent Engineering

Bootstrap file for coding agents that read `AGENTS.md` (Codex and similar).

**This file is deliberately short.** The repository maintains exactly one routing
entry point, and it is [`CLAUDE.md`](CLAUDE.md) — domain placement rules, the
authoring decision tree, and pointers onward. The exhaustive task → resource
tables live one hop away in [`meta/ROUTING_REFERENCE.md`](meta/ROUTING_REFERENCE.md);
open that only when you need it. Do not rely on a routing table duplicated here;
there no longer is one, because keeping several in sync by hand is what made
them disagree.

---

## What this repository is

**Prompt & Agent Engineering (PAE)** is an open-source registry of reusable
prompts, prompt-engineering techniques, skills, agents, commands, personas, and
agent-system designs, plus the generators and validators that keep them
governed.

Counts above are generated by `scripts/generate_repo_facts.py` and verified in
CI. Membership rules are in [`meta/REPOSITORY_FACTS.json`](meta/REPOSITORY_FACTS.json).

The **PAE Engine** is an installable package at [`pae-engine/`](pae-engine/)
providing identity resolution, policy-gated content serving, deterministic
lexical search and task routing. Context compilation and MCP access are still
planned. See [`ARCHITECTURE.md`](ARCHITECTURE.md) and
[`ROADMAP.md`](ROADMAP.md).

**If the Engine is installed, route first.**

```bash
pae route  "<task>"     # which scope and kind should handle this, and why
pae search "<task>"     # ranked resources, with the matched terms shown
```

`pae route` may answer `ambiguous`, `weak` or `no_route` — that is a result,
not an error, and every status exits 0. The prose routing guidance below
remains the fallback when the Engine is not installed, and it stays the
authority for everything the registry cannot represent: authoring policy,
safety conventions, negative boundaries and ordered workflows.

## Working rules

1. **Reuse before authoring.** Run `pae search "<what you were about to
   write>"` — or search `PROMPT_INDEX.json` and `domain-agentic-resources/` if
   the Engine is not installed — before creating a new resource. Creating a
   near-duplicate is the defect the registry structure exists to prevent.
2. **Never hand-edit generated counts.** Any number inside a
   `REPO_FACTS` block or an `INVENTORY_COUNTS` declaration is generated. Change
   the repository, then regenerate; CI fails on manual edits and on missing
   declarations.
3. **Do not modify vendored resources.** Files registered in
   [`meta/VENDORED.tsv`](meta/VENDORED.tsv) and the upstream skills recorded in
   [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md) are byte-identical to
   their sources on purpose.
4. **Frontmatter cross-references use repository-relative POSIX paths.** New or
   modified `related_prompts` entries must resolve from the repository root;
   `scripts/check_frontmatter_references.py` enforces this against a baseline.
5. **Run the validators before proposing changes.** See the `Validate` workflow
   in [`.github/workflows/validate.yml`](.github/workflows/validate.yml) for the
   authoritative command list.

## Token efficiency

`meta/ROUTING_REFERENCE.md` is large — grep it, or read the one section you need;
never load it whole. Read any reference file once, extract what you need, and work
from that. The "Token efficiency rules" section at the end of `CLAUDE.md` is the
full policy and applies to every agent working here, not only Claude.
